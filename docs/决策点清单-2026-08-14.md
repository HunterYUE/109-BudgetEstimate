## 1. B7 · 含税/未税契约分叉（Budget · project_versions 列）✅ [已定 2026-08-14 · 采纳文档对齐实现]

| 项 | 内容 |
|---|---|
| **现状** | 规则文档口径：「明细列未税、展示 ×(1+税)」；代码实际**存含税**、展示不乘（前端自洽，后端消费方不二次计税） |
| **影响** | 契约文档与实现长期分叉；无功能错误，但新接手者按文档理解会双重计税 |
| **改动风险** | 改动任一侧（存改未税，或展示改乘）都有**双重计税风险**——消费方可能已按现有约定二次计税 |
| **建议动作** | **文档对齐实现（零代码风险）**：将契约明确为「列持久化含税、明细展示未税换算、汇总含税」，写入家族清单/规范。代码不动 |
| **契约定稿** | ① `project_versions.discounted_price` **列持久化含税**；② 明细展示/参与计算须 `÷(1+taxRate)` 转未税（`exAmount`）；③ `calcProjectSummary` **必须传未税 discountedPrice**，返回 `totalAccountingPrice`/`discountedPrice` 为**含税**；④ 报价汇总（预期总价/折后报价）按含税展示；⑤ 全应用金额按未税处理，仅概算汇总三处含税（[[tax-rule]]）。**代码不动，仅契约文档对齐** |

## 3. D1 · 历史周编辑权限（TR · TimeRecord）✅ [已定 2026-08-14 · 补录窗口 = 当前周 + 前 4 周]

| 项 | 内容 |
|---|---|
| **现状** | 唯一门禁是 `weekFrozen`（已提交周冻结）；历史未提交周可自由编辑/增删（补录） |
| **影响** | 规则文档写「当前周开放；历史周只读」，但产品允许补录是有意设计 |
| **改动风险** | 锁定历史周会**阻断补录**（如漏记一周后无法回填） |
| **建议动作** | **已确认补录允许**，规则简化为：**当前周 + 前 4 周可补录，超过 4 周锁定**。截止点 = 当前周周一 − 4 周（按日期比较，落在周界）。前端按日期冻结截止点前格子（含 _other 删除、提交按钮 weekLocked）；后端 POST/PUT/DELETE/submit 加 `assertBackfillWindow` 权威校验（服务器北京时区算当前周周一） |

## 4. D2 · 补班日请休假（TR · TimeRecord）✅ [已定 2026-08-14 · 补班日 = 工作日]

| 项 | 内容 |
|---|---|
| **现状** | `MAKEUP_WORKDAYS`（周六补班）计入应出勤分母，但 `validateGrid` 对周末一律拒请休假 → **补班日请假被拦、开工率分母不减** |
| **影响** | 补班日请假无法提交（后端 `assertLeaveValid` 同样按周末拒，注释明确「MAKEUP_WORKDAYS 仅前端使用」） |
| **改动风险** | 支持补班日请休假需**前后端同改 + HR 规则确认**（补班日的请假口径、调休规则） |
| **建议动作** | **已确认允许补班日请休假，补班日=工作日**：后端同步 `MAKEUP_WORKDAYS` 日历（与前端 holidays.js 一份，对齐 STATUTORY_HOLIDAYS 同步契约），`serverHourType` 对补班日返回 `normal`（出勤/请假均按正常工作日计，不再判加班）；前端 `validateGrid` 豁免补班日（导出 `isMakeupWorkday`）。连带：加班统计不再含补班日（口径修正） |

**落地记录（2026-08-14）**：前端 `holidays.js` 导出 `isMakeupWorkday`、`TimeRecord.validateGrid` 豁免补班日；后端加 `MAKEUP_WORKDAYS` + `isMakeupWorkday`，`serverHourType` 对补班日返回 `normal`（晚段仍判加班）。**历史数据回填 `migrations/045-tr-makeup-workday-normal.sql`**：补班日存量 `hour_type='overtime'`（非晚段重叠）→ `'normal'`，使加班统计口径前后一致——数据影响项，部署前已确认。

## 5. D3 · 全天请休假上限口径（TR · TimeRecord）✅ [已定 2026-08-14 · 日净工时 8h，保留 8h 上限（零代码）]

| 项 | 内容 |
|---|---|
| **现状** | 前端 `TimeRecord.jsx` L141 与后端 `assertLeaveValid` L113 均为 8h：请休假单日合计 ≤ 8 小时 |
| **前提核实（2026-08-14 用户拍板）** | **日净工时 = 8 小时**——正常上满一天计 8h 工时，**非 9h**。时段跨度上午(4.5)+下午(4.5)=9h 仅为起止跨度（08:00-12:30 / 13:00-17:30），考勤/开工率分母按 `ATTENDANCE_DAILY_HOURS=8` 计 |
| **影响** | 全天请假 = 8h，**天然落在 8h 上限内**——不存在「被拦」缺陷。此前方案 A（上限 8h→9h）基于「日净工时 9h」的错误前提，**已撤销，代码已还原** |
| **结论** | **保留 8h 上限，零代码改动**。全天请假按 8h 录（如上午 08:00-12:00 + 下午 13:00-17:00）。连带决策（leaveHours 日封顶 8h）：因 8h 上限已强制单日请休假 ≤8h，`leaveHours` 累加天然 ≤8h/日，**无需额外改动** |
