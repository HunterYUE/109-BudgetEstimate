# 注释规范（Comment Standard）

> **适用**：共享后端（`backend/src`）、预算应用 Budget（`BudgetEstimateApp/src`）。
> **目的**：注释风格单一、内容有效、行文正式；只保留解释「为什么」的当前不变量，不留历史档案。

---

## 1 区段标题

函数体 / 代码块分组标题使用行注释，双侧闭合，标题与横线之间各留一个空格：

```ts
// ── 聚合：按成本中心 ──
```

- 不使用 `// ===== 标题 =====`、`// ---- 标题 ----`、手工填充对齐的横线。
- JSX 结构标题使用 JSX 注释：`{/* ── 桌面侧边栏 ── */}`。
- 文件头 / 模块级说明使用多行 `/** ... */`。

## 2 函数与常量说明

默认使用单行散文式说明：

```ts
/** 按成本中心编号格式推断类型，未识别返回 other */
export function inferType(code: string) { ... }
```

需要说明参数或返回值时才使用多行标签：

```ts
/**
 * 检查权限数组是否允许访问指定路由
 * @param permissions 用户权限列表
 * @param path 请求路径
 */
```

- `*` 后固定一个空格，续行与 `/**` 左对齐。
- 注释句末不加句号；句内分句使用中文分号。
- 不强制为每个函数补 `@param` / `@returns`，避免不完整的 JSDoc。

## 3 决策说明

重要约束使用普通注释陈述当前规则与原因，不使用警示图标、审计批次号或日期：

```ts
// 并发审批以行锁串行化，避免重复写入审批记录
```

- **禁止**图标与符号：`⚠️`、`✅`、`❌`、`★`、`✔` 等。
- **禁止**批次号与编号：`A1`、`B61`、`F02`、`C101`、`BE-7`、`#12` 等。
- **禁止**历史叙述：`此前……`、`原实现……`、`旧实现……`、`已删除……`、`2026-08-13 修复……`。
  历史由 git log 保存，注释只描述当前实现与原因。
- 需要强调时使用 `注意：`，不使用图标。

## 4 语言

注释一律中文。技术术语、标识符、接口路径、命令与代码片段可保留英文。

## 5 行内注释

逻辑行尾注释格式：代码 + 单空格 + `//` + 单空格 + 说明；句末不加句号。

```ts
const mountedRef = useRef(false); // 卸载守卫：异步回调不得在卸载后触发
```

- 整行注释统一为 `// 说明`（`//` 后一个空格），续行保持相同缩进。
- interface / 字段声明允许列对齐，为唯一例外。

## 6 无效注释（必须删除）

- 孤儿 JSDoc（描述的函数已不存在）。
- 纯装饰分割线（无标题信息）。
- 复述代码的注释（`// 删除`、`// GET BY ID`）。
- 注释掉的代码。
- 过时的历史说明与已被替代的实现描述。
- 同一规则多处复述：收敛到定义处单源说明，引用点简化为「见 xxx」。

## 7 自查

每批代码提交前检查：

1. 区段标题是否为 `// ── 标题 ──`。
2. 是否出现图标、批次编号或日期。
3. 是否残留「此前 / 原实现」等历史叙述。
4. 行内注释是否保持单空格格式。
5. 注释句末是否误加句号。
6. `*` 续行是否为一个空格并左对齐。
7. 测试与脚本注释是否同样遵守本规范。
8. 新增纯函数是否有中文说明与测试。
