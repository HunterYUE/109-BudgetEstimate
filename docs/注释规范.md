# 注释规范（Comment Standard）

> **适用**：共享后端（backend/src）、预算应用 Budget（BudgetEstimateApp/src）、工时应用 TR（D:\108-TimeRecording\frontend/src）。
> **依据**：2026-08-13 三套代码库注释全量勘察 + 统一整理（git log 可溯源）。
> **目的**：注释风格单一化、无效注释清零、让「为什么」类决策注释存活、随迭代不沦为过时噪音。

---

## 1. 区段标题

函数体 / 代码块分组标题一律用行注释，双侧闭合、不手工填充对齐：

```js
// ── 聚合：按成本中心 ──
```

- ❌ 不用 `// ===== 标题 =====`、`// ---- 标题 ----`、`// ─── 标题 ──────`（手工对齐填充）、`/* ── 标题 ── */`
- JSX 结构标题用 JSX 注释：`{/* ── 桌面侧边栏 ── */}`
- 文件头 / 模块级说明用多行 `/** ... */`

## 2. 函数 / 常量说明

- 默认**单行散文式** `/** 中文说明 */`：

```js
/** 按成本中心编号格式推断类型（未识别 → 'other'） */
export function inferType(code) { ... }
```

- 仅当需要参数/返回值语义时才用多行 + 标签：

```js
/**
 * 检查权限数组是否有权访问指定路由
 * @param permissions 用户权限列表
 * @param path 请求路径
 */
```

- 不为每个函数强制补 `@param`/`@returns`（现状仅少量需要，避免半吊子 JSDoc）。

## 3. ⚠️ 修复标记（决策历史）

`⚠️` 前缀注释是**决策历史**（A1/C106 等：为什么这么改），价值高，**保留内容**。格式归一：

```
// ⚠️ <编号> 修复：<为什么这样写>
// ⚠️ <描述>：<为什么这样写>
```

- `⚠️` 后单空格；标签后统一中文冒号；多余空格折叠
- 只陈述**当前为什么不变量**，删除「此前做了什么/旧口径/已删除」的纯历史叙述（历史已在 git log，注释里不再留档）

### 编号纪律（⚠️ 的编号是历史批次号，不是语义分类号）

编号（A1/C106 等）是**历史审计批次标识**，只回答「哪个修复」，不承载语义（A 不一定代表"审计"，B 不一定代表"Bug"）。**存量编号（三套约 229 个）一律不动**：

- **不重排、不回收、不补断号**：A1/A3/A7 之间的空号是不同批次的编号池，非漏号；重排会切断测试用例名（route-guards.test.ts 锚定 A2/A3/A101/C106）、docs、记忆等 150+ 处外部引用，且 git 历史里的旧编号无法同步修改，必然产生新旧双轨并存。
- **不按语义重新归类字母前缀**：后端 A/F/L/M/K/H/C/S、Budget B/A/L/D/F/M、TR C/S/T/L/A/B 各自成池，是历史事实；重新归类同样破坏引用链。
- **新增编号沿用所在代码库既有字母池，只递增不重用**：
  - 后端：A / F / L / M / K / H / C / S
  - Budget：B / A / L / D / F / M
  - TR：C / S / T / L / A / B
- **已落地的引用（测试用例名、文档、记忆）永不改名**——它们与注释编号互为检索锚点。

## 4. 语言

注释一律中文（技术术语、标识符、`// POST /api/...` 路径除外）。不写英文散文注释。

## 5. 行内注释

逻辑行尾注释：`代码 + 单空格 + // + 单空格 + 说明`。

```js
const mountedRef = useRef(false); // 卸载守卫：异步回调不得在卸载后触发
```

- 例外：interface/字段声明（types.ts 等）保留列对齐，作为唯一显式例外。

## 6. 无效注释（必须清）

- 孤儿 JSDoc（doc 描述的方法已不存在）
- 纯装饰分割线（`/* ===…=== */` 无标题信息）
- 数字裸注释（`// 803`）与自明复述（`// GET BY ID`、`// 删除所有节点`）
- 重复解释：同规则多处复述 → 收敛到定义处单源说明，引用点简化为「见 xxx」

## 7. 自查

每批代码过注释规范：新写区段标题用 `// ── 标题 ──`？新写说明用单行 `/** */`？⚠️ 只写「为什么」不写「此前」？行内单空格？新增纯函数注释中文？
