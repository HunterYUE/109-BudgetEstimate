# 家族缺陷清单（Family Defect Checklist）

> **用途**：后续每批代码（新功能 / 修复 / 重构）按此清单自查，防同类缺陷复发。
> **覆盖**：预算应用 Budget（D:\109-BudgetEstimate）、工时应用 TR（D:\108-TimeRecording）、共享后端。
> **依据**：五轮全量审计（含 2026-08-14 双应用业务逻辑/规则审计）+ 18 项已修缺陷 + 单测暴露的契约真相 + 历次开发日总结（git log 可溯源）。

## 使用方法

写代码前 / 后各过一遍。**命中任一家族** → 按「现有防线」落实或补一条单测，再合入。
重点触发点：新增接口、改状态字段、动金额/日期/权限/导出、动共享逻辑、新增枚举。

## F01 输入边界与防御
- **症状**：垃圾输入撞 DB 约束返 500；null 撞 NOT NULL；非数组破坏前端展开；超大数组撑大行；缺失字段无兜底。
- **已修实例**：任务 status 应用层枚举预校验（0debab9）、PUT history 数组校验 ≤200 条、POST 目标员工须在职（653ea34）、color 缺失兜底默认色、蓝表 influenceWeight 0/NaN 防御。
- **2026-08-14 双应用业务规则审计补防**：approvals POST approval_type 枚举白名单（防 PG 枚举错误 500）、deliveries nodes PUT node.status 枚举白名单 + node.history Array.isArray 校验（防畸形 JSON 入库、渲染 .find/.map 崩溃）。
- **现有防线**：单测覆盖非法枚举/空值/畸形数据（blueTableCalculation / costCenter.buildCcGroups / tableUtils 等）。
- **自查**：新写 POST/PUT——非法枚举、null、超长、非数组分别会怎样？是否在应用层返回明确 400 而非 500？是否有确定性兜底形状？

## F02 状态机与权限绕过
- **症状**：请求体可直设业务状态绕过审批；权限守卫 OR 语义（任一命中即放行）导致越权写；角色等级可越级管理。
- **已修实例**：quotations excludeOnCreate 补 status、deliveries 禁直设 plan_status/cost_status+伪造 JSONB、project-versions review_status 枚举校验、writeGuard 剔除只读页面权限（A1-A6）、director 不能再管理 admin（ROLE_RANK 纯等级比较）。
- **2026-08-14 双应用业务规则审计补防**：timerecording POST /admin/users **创建**路径补 assertCanManage（reset-password 早有、创建路径漏——director 可铸 admin 号；现与 users.ts/重置路径同级防线）；DeliveryDetail 节点15「已完成」门禁 = 成本审批 + **其余全部节点 completed**（原仅查成本审批，可提前完结导致分析把未完成项目计为已交付）。
- **2026-08-14 P1 报价降级契约锁定（B4）**：QuotationPage 保存已通过/已驳回报价须降级 draft（B61 防绕过状态机——改过数据不经重审仍显示"已通过"）；`reviewStatusForSave` 提取纯函数锁定（approved/rejected→draft、pending/draft 不动）+ 降级时 messageApi.warning 提示（UX 不再静默）。单测：tests/quotationStatus.test.ts。
- **现有防线**：单测锁定（2026-08-13 路由行为层）：route-guards.test.ts 覆盖 computeInsertCols 剥除状态字段（A2/A3）、selectApprovalPerms/selectDeliveryPerms 守卫选择映射（A1/A101）、审批状态机纯函数、index.ts 静态接线断言（禁止内联权限数组进守卫）；permissions.test.ts 配置漂移回归（只读权限不得混入写守卫）+ 验收测试点。
- **自查**：新写写接口/状态字段——能否从请求体直设业务状态？权限守卫用 some() 还是 every()？目标角色等级是否 > 操作者等级？

## F03 竞态与并发
- **症状**：读-判断-写三段不同事务 → 并发双击双审批；快速连点打开编辑竞态。
- **已修实例**：审批终审状态检查移入事务 + SELECT FOR UPDATE（A7）、ClientManagement openEdit pending ref 防连点（B5）。
- **自查**：判断与写入是否在同一事务？是否加行级锁？按钮/打开操作是否有 pending/loading 防抖？
- **覆盖方式（2026-08-13 确认）**：后端 A7 竞态守卫是 DB 级机制（终审检查入事务 + SELECT FOR UPDATE 行级锁），无 mock 规则下不可单测——覆盖 = 事务+行级锁设计 + 验收测试 + 代码审查；前端 B5 类防连点（pending ref）为组件交互态，需 jsdom 环境才能测，暂归验收。两项均不再考虑补单测。

## F04 数值精度与金额口径
- **症状**：浮点噪声 12.300000000000001 扩散；金额口径分叉（未税/含税混用）；`|| 1` 把合法 0 变 1；四舍五入方向误解。
- **已修实例**：全应用金额按未税、仅概算汇总含税（tax-rule）、TAX_RATE 收敛 constants、`qty_total || 1`→COALESCE（A8）、round1/round2 浮点纪律。
- **2026-08-14 双应用业务规则审计补防**：`qtyTotal || 1` 全量扫净 → `?? 1`（calculations.ts ×3 + costBreakdown.ts ×5；数量可输入 0 且 DB 无 CHECK>0，`|| 1` 把合法 0 虚增为 ×1 成本；`?? 1` 缺省仍按 1、显式 0 保留为 0）。
- **现有防线**：单测覆盖 formatMoney/exAmount/round1/effectiveWorkHours 浮点用例。
- **自查**：金额走统一未税口径了吗？取整用 round 且知道 Math.round(-25.5)=-25 吗？`||` 兜底会不会吞掉合法 0？累加后是否 round 去噪声？

## F05 时区与财年边界
- **症状**：月末漏最后一天数据；财年归属误用 updatedAt；toISOString 时区偏移差一天。
- **已修实例**：月末排他边界 23:59:59.999（monthEndOf/parseFY）、财年归属核心原则（有效结束=业务完结事件，永不用 updatedAt，见 analysis-fiscal-year-logic）、formatBeijing 去 toISOString 往返（B26）、formatDate 本地拼接。
- **现有防线**：单测覆盖 parseFY/fiscalYearLabel/fyMonthWindows/oppEffectiveEnd/getProjectDoneDate。
- **自查**：月末/年末边界是否含 23:59:59.999？财年归属用业务事件还是 updatedAt？活跃期/订单/销售归集口径与同源函数一致吗？

## F06 HTML 注入与导出安全
- **症状**：用户可控文本进 HTML 破坏表格结构/注入；width 等属性上下文未转义；文件名含 Windows 非法字符下载失败。
- **已修实例**：escapeHtml 全转义（B36）、dataTable width 过 esc、fileSafe 清洗 `\/:*?"<>|`。
- **现有防线**：单测覆盖 esc/escapeHtml/dataTable/fileSafe/exportDoc。
- **自查**：用户文本进 HTML 是否过 esc？进 style/属性上下文是否过 esc？导出文件名是否清洗？

## F07 认证与会话安全
- **症状**：登录错误信息泄露邮箱枚举；email 未归一化；限速按代理 IP 失效；默认密码明文展示；删除/读取缺守卫。
- **已修实例**：登录恒等假比较防枚举 + email LOWER/TRIM（A5）、trust proxy=1 按真实 IP 限速、登录审计非阻塞、admin 重置密码 404、SystemManagement 默认密码收敛（B27）。
- **自查**：登录失败是否统一文案？email 存取是否归一化？限速/审计是否被异常阻塞？新鉴权接口有无权限/删除守卫？

- **症状**：catch(_) 静默吞错，故障不可见；聚合拉取被截断仍算出错数。
- **已修实例**：6 处通知 catch→console.warn、unhandledRejection 兜底、checkTruncation 截断告警（LIST_LIMIT 100000）。
- **现有防线**：单测覆盖 checkTruncation 告警。
- **自查**：catch 里吞掉错误了吗？有 console.warn 吗？聚合/全量拉取是否感知截断？

## F10 前后端契约一致性
- **症状**：后端响应与前端 TS 类型不符（currentVersion 反复故障）；camelCase↔snake_case 转换职责混乱。
- **已修实例**：currentVersion 契约修复模式、toSnake 统一转换职责。
- **现有防线**：单测锁共享函数输入/输出形状。
- **自查**：新接口返回与前端类型严格一致？键名转换统一走 toSnake？响应键名/类型变更是否同步前端类型？

## F11 性能与渲染
- **症状**：columns/映射渲染期重建 → 整表重渲染；O(N²) 嵌套遍历；无虚拟化上千行卡死。
- **已修实例**：columns useMemo 去数据依赖（B7）、bubbleData 单遍 Map（B8）、甘特日格渐变背景去 196 div/行（C6）、统计表 scroll.y+virtual（C7）。
- **自查**：columns/选项/映射是否渲染期内联重建？遍历是否嵌套 O(N²)？大数据表格是否虚拟化？

## F12 测试基建纪律
- **症状**：测试造假数据/打网络桩；测试依赖 now；vi.mock 引发 TDZ 或未处理拒绝误报。
- **规则（硬约束）**：
  - **数据必须是真实数据库形状**，直接作参数传入；**禁止 vi.mock 打桩业务/网络层**（costCenter 已提取 buildCcGroups 纯函数去 mock 为范例）。
  - 测试放根级 `tests/`（规避 Budget lint-naming）；vitest 已挂进 build 门禁，失败即构建失败。
  - 涉 now 的函数须 asOf 注入；vi.hoisted 解决 TDZ；async-throw 用 mockImplementation(async throw) 而非 mockRejectedValue。
- **自查**：新纯函数加单测了吗？数据是真实形状、无 mock 吗？`npm run build` 跑得过吗？
  - **静态接线断言**（route-guards 先例）：对无法实例化（依赖 DB/中间件链）的接线层（如 routes/index.ts 守卫挂载），可直接 `fs.readFileSync` 读源码断言结构不变量（禁内联权限数组、须引用配置常量）——非 mock，锁「配置收敛」类回归。
- **2026-08-14 门禁补漏 + 覆盖提升**：TR build 此前仅 vite+vitest、**无 eslint**——react-hooks/purity（渲染期 `Date.now()` 改 `useNow()`）与 no-useless-escape 共 4 error 漏网；已接入 `eslint . --quiet` 进 build（+coverage ignore）。后端覆盖率 5.81%→10.61%：timerecording 11 个服务端权威纯函数 export（toMinutes/serverHours/serverHourType/isoWeekOf 等）+ errorHandler `pgErrorResponse` 提取，+37 测试均真实 DB 形状直测无 mock（F12 硬约束）。

## 每批代码提交前快检（30 秒）

1. 新增/改动接口 → F01 输入边界 + F02 状态机/权限 + F10 契约
2. 动金额/数量 → F04 金额口径 + 数值精度
3. 动日期/财年 → F05 边界 + 归属
4. 动权限/认证 → F02 + F07
5. 动导出/字符串拼接 → F06
6. 动共享逻辑/枚举 → F08（含 HMR 显示同步）
7. 动数据拉取/循环 → F11 + F09 截断
8. 新增纯函数 → F12 补单测
