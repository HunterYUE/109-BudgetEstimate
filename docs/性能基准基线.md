# 性能基准基线（Performance Baseline）

> **用途**：批量处理纯函数（上千行挂载 / 全量聚合）的可复现耗时基线，防灾难级回归。
> **机制**：`tests/bench/` + `vitest.bench.config.*`，`npm run bench` 运行——**测量工具、无断言、不进 build 门禁**（`*.bench.*` 命名天然不被默认 `*.test.*` include 匹配）。`disableConsoleIntercept: true` 让 console.table 直通 stdout。
> **数据纪律**：基准夹具同样用真实数据库形状、无 vi.mock（与 F12 同约束）。bench 文件 `as any` 会被 lint-naming 抓警告，用 `as Group` 之类精确类型。
> **机器**：本机（Windows 11），数字为 20 次取中位数。基准随硬件浮动，**不作为断言阈值**——大型重构触碰热路径时人工对比本表即可。

## Budget（BudgetEstimateApp）

```bash
cd BudgetEstimateApp && npm run bench   # vitest run --config vitest.bench.config.ts
```

| 函数 | 样本 | 中位耗时 | 吞吐 |
|---|---|---|---|
| `buildCostLines`（成本对比行） | 200 组 × 10 项 = 2000 行 | 0.28 ms | ~3.4k ops/s |
| `computeCostComponents`（成本汇总） | 2000 行 | 0.05 ms | ~18.5k ops/s |

建立于 2026-08-13（f2c3367）。

## 何时回跑

- 触碰 `costBreakdown.buildCostLines` / `calculations.computeCostComponents` / `timeStats.*` 的实现或调用方
- 数据量级变更（如 LIST_LIMIT 调整）
- 每次引入新的批量纯函数前，建议先 bench 立基线再改
