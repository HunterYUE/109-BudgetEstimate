## 13.1 crudRoutes 工厂（后端的地基）

后端大量资源（物料、项目、客户、标签、审计）都是标准 CRUD。`crudRoutes(table, fields, options)` 用一行配置生成全套：

```ts
export function crudRoutes(table: string, fields: string[], options?: {
  orderBy?: string;                 // 列表排序，默认 created_at DESC
  searchFields?: string[];          // 搜索字段（ILIKE 转义后 OR 连接）
  excludeOnCreate?: string[];       // ★ 创建时禁直设的列
  excludeOnUpdate?: string[];       // ★ 更新时禁直设的列
  beforeCreate?: (body) => Promise<void>;   // 创建前业务不变量校验
  beforeUpdate?: (id, body) => Promise<void>; // 更新前状态机守卫
  beforeDelete?: (id) => Promise<void>;      // 删除前引用检查
  afterUpdate?: (req, id, body, row) => Promise<void>; // 更新后钩子（审计）
  textArrayCols?: string[];         // TEXT[] 列（空数组序列化 '{}'）
  skipList?: boolean;               // 顶层已自定义列表时跳过
  skipUpdate?: boolean;             // 顶层已自定义更新时跳过
}) { ... }
```

### 13.1.1 生成的 5 个端点

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/` | 列表：search + pagination + orderBy |
| GET | `/:id` | 单条，找不到 404 |
| POST | `/` | 创建：`computeInsertCols` 过滤 + 只插有值的列 |
| PUT | `/:id` | 更新：`computeInsertCols` 过滤 + 更新为有值的列 |
| DELETE | `/:id` | 删除：`RETURNING` 检查行数，不存在 404 |

### 13.1.2 computeInsertCols：排除列的契约核心

```ts
export function computeInsertCols(fields, exclude, snakeBody): string[] {
  return fields.filter(f => !exclude.includes(f) && snakeBody[f] !== undefined);
}
```

**这是"状态机防绕过"的列构造层防线**（A2/A3 修复）：`excludeOnCreate`/`excludeOnUpdate` 里的字段（如 `status`、`locked`、`plan_status`）即便请求体传了也被**剥除**，根本不进 INSERT/UPDATE 语句。

测试锁定的契约（`tests/route-guards.test.ts`）：

```ts
// excludeOnCreate 中的字段即便请求体传入也被剥除（POST /quotations 直设 status）
const cols = computeInsertCols(fields, ['id', 'status', 'locked'], { status: 'approved', locked: true, amount: 100 });
expect(cols).not.toContain('status');   // status 被剥
expect(cols).not.toContain('locked');   // locked 被剥
expect(cols).toContain('amount');       // 普通字段保留
```

⚠️ **边界**：`!== undefined` 判定（不是 `!== null`、不是 truthy）——所以 `0`/`''`/`false` 这些**合法值仍能插入**，只有 `undefined`（没传）才被过滤。

### 13.1.3 钩子的典型用法

```ts
// components.ts（物料）：删除前引用检查
beforeDelete: async (id) => {
  const used = await query('SELECT 1 FROM group_items WHERE component_id = $1 LIMIT 1', [id]);
  if (used.rows.length) throw new AppError(409, '该物料已被报价引用，无法删除');
}

// quotations.ts（报价）：更新前状态机守卫
beforeUpdate: async (id, snakeBody) => {
  // 审批中（pending）禁改财务字段
  const existing = await query('SELECT status FROM quotations WHERE id = $1', [id]);
  if (existing.rows[0]?.status === 'pending' && 存在财务字段变更) throw new AppError(409, '报价审批中，不可修改财务字段');
}
```

**钩子的语义**：抛错 → 阻断操作，返回错误状态码；不抛 → 放行。它们把"业务不变量"放在靠近 SQL 的地方，保证无论从哪个前端调用都生效。

## 13.2 新增一个 CRUD 资源的完整配方

**需求示例**：给系统加一个"供应商表"（`suppliers`）。

### 步骤 1：建表（迁移 + schema.sql）

写 `backend/migrations/046-add-suppliers.sql`：
```sql
CREATE TABLE IF NOT EXISTS suppliers (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(200) NOT NULL,
  contact VARCHAR(100) NOT NULL DEFAULT '',
  phone VARCHAR(50) NOT NULL DEFAULT '',
  note TEXT NOT NULL DEFAULT '',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```
**同一 commit 同步** `BudgetEstimateApp/database/schema.sql`（加对应 CREATE TABLE + 触发器）。

### 步骤 2：建路由文件 `routes/suppliers.ts`

```ts
import { Router } from 'express';
import { crudRoutes } from './helpers.js';

const router = Router();
const fields = ['id', 'name', 'contact', 'phone', 'note', 'created_at', 'updated_at'];

router.use(crudRoutes('suppliers', fields, {
  orderBy: 'created_at DESC',
  searchFields: ['name', 'contact'],
  excludeOnCreate: ['id', 'created_at', 'updated_at'],
  excludeOnUpdate: ['id', 'created_at', 'updated_at'],
}));

export default router;
```

### 步骤 3：挂载 + 接守卫（routes/index.ts + permissions.ts）

```ts
// routes/index.ts
import suppliers from './suppliers.js';
router.use('/suppliers', requireAuth, writeGuard(WRITE_GUARD.suppliers), readGuard(READ_GUARD.suppliers), suppliers);

// permissions.ts
WRITE_GUARD.suppliers = ['新增物料', PERM_ALL];        // 例：供应商管理归物料管理员
READ_GUARD.suppliers = ['物料管理', '报价编制', '交付管理', PERM_ALL];
```

### 步骤 4：前端四件套

1. `types.ts` 加 `Supplier` 类型；
2. `services/supplierService.ts`：
   ```ts
   export const supplierService = {
     list: (params?) => api.get<Supplier[]>('/suppliers' + (params ? '?' + new URLSearchParams(params).toString() : '')),
     create: (data) => api.post<Supplier>('/suppliers', data),
     update: (id, data) => api.put<Supplier>(`/suppliers/${id}`, data),
     remove: (id) => api.delete(`/suppliers/${id}`),
   };
   ```
3. `pages/SupplierList.tsx`（照抄 12.1.1 列表页骨架）；
4. 注册四件套：`App.tsx` 路由 + `pageLoaders.ts` 懒加载 + `AppLayout.tsx` 菜单 + `permissions.ts` 路由权限。

### 步骤 5：测试 + 门禁

- 若业务有状态机，补 `route-guards.test.ts` 风格的排除列断言；
- 跑 `npm run build` 五关。

## 13.3 新增一个自定义业务端点（有状态机的资源）

模板（以"供应商停用"为例）：

```ts
router.put('/:id/deactivate', asyncHandler(async (req, res, next) => {
  const { id } = req.params;
  // 1. 权限检查（如果不是全路由统一守卫，这里显式加）
  if (!hasPermission(req.user?.permissions, '新增物料', '全部查看权限')) throw new AppError(403, '权限不足');
  // 2. 业务不变量校验（服务端权威）
  const sup = (await query('SELECT * FROM suppliers WHERE id = $1', [id])).rows[0];
  if (!sup) throw new AppError(404, '供应商不存在');
  if (sup.status === 'inactive') throw new AppError(409, '供应商已是停用状态');
  // 3. 写操作（跨表用 withTransaction）
  await query('UPDATE suppliers SET status = $1 WHERE id = $2', ['inactive', id]);
  // 4. 审计
  logAudit(req, '停用供应商', 'material', `供应商「${sup.name}」已停用`);
  res.json({ id, status: 'inactive' });
}));
```

**asyncHandler** 是 helpers.ts 的公共封装：

```ts
function asyncHandler(fn: AsyncHandler) {
  return (req, res, next) => { fn(req, res, next).catch(next); };
}
```

它把 async 函数的 reject 交给 `next(err)` → 最终落到 `errorHandler`。**避免每个路由手写 try/catch**。

## 13.4 事务：withTransaction

```ts
export async function withTransaction<T>(fn: (client: any) => Promise<T>): Promise<T> {
  const client = await getClient();
  try {
    await client.query('BEGIN');
    const result = await fn(client);
    await client.query('COMMIT');
    return result;
  } catch (e) {
    await client.query('ROLLBACK').catch(() => {});
    throw e;
  } finally {
    client.release();
  }
}
```

**什么时候必须用事务**：跨表/级联写。比如：
- 创建审批 + 级联置 pending/locked（09 章）；
- 蓝表 upsert + 整组替换角色（opportunities.ts）；
- 节点整组替换（先删后插）；
- 创建用户 + 创建工时档案。

**什么时候不需要**：单表写。事务有开销，别滥用。

⚠️ 事务内的 `client.query` 必须用事务客户端（`client`），不能用模块级 `query`——后者走连接池的**另一个连接**，不在事务里！

## 13.5 审计：logAudit

```ts
export async function logAudit(req, action, module, detail = '') {
  const user = req.user;
  const userName = user?.email || 'anonymous';
  try {
    await query(`INSERT INTO audit_logs (time, user_name, action, module, detail) VALUES (now(), $1, $2, $3, $4)`, [userName, action, module, detail]);
  } catch (err) { console.error('[Audit] 写入审计日志失败:', err.message); }
}
```

- **非阻塞**：内部 try/catch，审计失败不影响业务（`fire-and-forget`）；
- 每次"关键操作"都调——登录、保存版本、审批、删除、改成本；
- `audit_logs` 路由**只读**（没有写接口），审计数据不可篡改。

## 13.6 越级保护与权限授予

**涉及账号/角色等级的操作**，一律先过 `assertCanManage`：

```ts
// users.ts 创建用户
if (!hasPermission(req.user?.permissions, '用户管理', '全部查看权限')) throw new AppError(403, '权限不足');
assertCanManage(req.user!.role, ROLE_RANK[role] ?? 0);   // ★ 不能创建比自己等级高的账号
```

**权限授予**（validatePermissionsGrant）双校验：
1. 白名单（`ALL_PERMISSIONS` 21 项）外 → 400；
2. **只能授出操作者自己已持有的权限** → 403（防横向放大）。

## 13.7 服务端权威计算的写法（timerecording 范本）

**规则**：凡是"算数、判状态"，写成 `export` 的无副作用纯函数，放文件顶部，供页面直接调用 + 测试直接测。

```ts
/** 加班判定：晚时段(18:00-20:30)重叠 OR 周末（补班日除外）OR 法定节假日 */
export function serverHourType(date?, start?, end?): 'normal' | 'overtime' { ... }

/** 补录窗口起点（D1 决策）：当前周 + 前 4 周 */
export function backfillWindowStart(now: Date = new Date()): string { ... }
```

测试配套（`tests/timerecording-core.test.ts`）用**真实数据形状直测、零 mock**：

```ts
describe('serverHourType 加班判定', () => {
  it('工作日白天 → normal', () => {
    expect(serverHourType('2026-08-14', '09:00', '12:00')).toBe('normal');  // 周五
  });
  it('晚时段重叠 → overtime', () => {
    expect(serverHourType('2026-08-14', '18:00', '20:30')).toBe('overtime');
  });
});
```

**为什么这样写收益最大**：
- 纯函数无副作用 → 测试不需要 mock 数据库/DOM/时间；
- `export` → 测试能 import；
- `now`/`asOf` 注入 → 涉时间的函数可测（传固定时刻）；
- 这些函数 = 业务规则的"编译后契约" → 后端覆盖率里纯函数层 80~100%。

## 13.8 错误处理约定

- **业务错误**：`throw new AppError(400, '中文提示')`；
- **PG 错误**：errorHandler 按错误码映射（`23505`→409"数据已存在"、`23503`→409"存在关联数据"、`22P02`→400"字段值无效"）——**不泄漏数据库结构**（detail 只进服务端日志）；
- **未知错误**：500"服务器内部错误"；
- **成功响应形状**：
  - 创建/更新返回**实体本身**（前端要回填 id）；
  - 纯动作（删除/重置密码）返回**动作信封**（`{ deleted: true }` / `{ success: true }`）。

## 13.9 本章小结

- `crudRoutes` = 一行配置生成 CRUD + 钩子 + 排除列；`computeInsertCols` 是状态机防绕过的列构造层。
- 新资源五步：建表 → route → 挂载守卫 → 前端四件套 → 测试。
- 自定义端点四件套：鉴权 → 业务校验 → 写操作（事务）→ 审计。
- 服务端权威 = 纯函数 + export + asOf 注入 + 测试锁定。
