# 03 代码库导航

> **本章学习目标**
> 1. 对三个 `src/` 目录做到"闭眼能画出来"——每个文件在哪、干什么；
> 2. 识别出 ★ 核心文件（学习优先阅读）；
> 3. 掌握一套适合入门者的代码阅读顺序。

> ⚠️ 本文件是"地图"。建议配合实际目录对照阅读，并在浏览器里打开对应文件。

---

## 3.1 共享后端 `backend/` 逐文件

### 入口与配置

| 文件 | 职责 | 读它之前先懂 |
|---|---|---|
| `src/index.ts` | Express 应用入口：**固定北京时区**（`process.env.TZ='Asia/Shanghai'`）、CORS/helmet/限速中间件、`/api/health` 健康检查、挂载路由、启动 3 个定时任务、优雅关闭、unhandledRejection 兜底 | 02 章 |
| `src/constants.ts` | 全局常量：`PAGE_LIMIT=100000`、`DEFAULT_PAGE_SIZE=100`、`PASSWORD_MIN=8`、默认税率/汇率/质保/风险率 | 02 章 |
| `src/permissions.ts` | ★ **权限守卫配置唯一来源**：`PERM_ALL`、`PAGE_VIEW_ONLY_PERMS`、`WRITE_GUARD`、`READ_GUARD`、`APPROVAL_WRITE`、`DELIVERY_*`、`findPageViewLeaks/selectApprovalPerms/selectDeliveryPerms` | 06 章 |
| `src/db/pool.ts` | pg 连接池 + **类型解析器**：NUMERIC(1700)→number、FLOAT→number、date(1082)→原样字符串（防时区偏移），环境变量校验 | 05 章 |
| `src/db/index.ts` | 导出 `query`/`getClient`/`pool`，`query` 带慢查询告警（>1s 打 warn） | — |

### 中间件

| 文件 | 职责 |
|---|---|
| `src/middleware/auth.ts` | ★ **认证核心**：JWT 签发/校验、HttpOnly cookie 读写（`budget_token`/`tr_token`）、`requireAuth`（每请求查库刷新权限 + 停用判定 + 改密吊销）、`requireRole`、`hasPermission`、`requirePermission`。逐行讲解见 06 章 |
| `src/middleware/errorHandler.ts` | `AppError`（带 statusCode）+ `pgErrorResponse`（PG 错误码→友好消息）+ 统一 errorHandler（Multer 错误、JSON 解析错误、通用 500） |
| `src/middleware/index.ts` | 汇总导出 |

### 路由模块（业务的核心都在这里）

| 文件 | 资源 | 核心内容 |
|---|---|---|
| `src/routes/index.ts` | ★ 路由总装配 | 挂载所有路由 + **读改写分离守卫接线** + 报价编制专属端点（`/project-versions`、`/project-groups`、`/project-groups/by-version/:versionId`） |
| `src/routes/helpers.ts` | ★ 共享工具 | `crudRoutes` 工厂、`withTransaction`、`parsePagination`、`buildSearchWhere`、`normalizeEmail`、`ROLE_RANK`/`assertCanManage`、`resetUserPassword`、`logAudit`、`objKeysToSnake`、`computeInsertCols`、`serializeParams`、`round2`。**后端学习优先读它** |
| `src/routes/auth.ts` | 认证 | `POST /login`（含假 bcrypt 比较防枚举、跨应用登录限制）、`GET /me`、`POST /logout`；`isRestrictedCrossAppUser`/`shapeAuthUser` 纯函数 |
| `src/routes/users.ts` | 用户管理 | 创建/更新/重置密码/改角色/删除；`validateNewUserInput`、`validatePermissionsGrant`（权限白名单+委托限制）、越级保护、自保护 |
| `src/routes/timerecording.ts` | ★ 工时系统（最大，~1200 行） | 全部工时端点 + **服务端权威工时计算**（toMinutes/serverHours/serverHourType/isoWeekOf/backfillWindowStart/assertBackfillWindow/assertLeaveValid 等）+ 角色派生（isTrAdmin/trRoleOf/isManager）+ 跨应用守卫 |
| `src/routes/approvals.ts` | ★ 审批状态机 | 4 类审批的创建/列表/详情/处理/删除；`buildOppStatusClauses` 级别的级联回写（见 09 章） |
| `src/routes/opportunities.ts` | ★ 销售机会 | 自定义列表（LEFT JOIN 蓝表/报价）、`buildOppStatusClauses` 状态机、蓝表 upsert、销售编号生成 |
| `src/routes/quotations.ts` | 报价摘要 | `PUT /quotations/sync` upsert（内联实现）、`QUOTATION_FINANCIAL` 白名单、beforeUpdate pending 守卫 |
| `src/routes/deliveries.ts` | 交付 | 节点整组替换、附件 multer 上传、成本覆盖 afterUpdate 审计、`normalizeNodeInsertParams`/`sanitizeFileName` |
| `src/routes/projects.ts` | 项目 | crudRoutes + `/:id/full`（含版本/组/明细） |
| `src/routes/components.ts` | 物料 | crudRoutes + 被报价引用禁删 |
| `src/routes/clients.ts` | 客户 | crudRoutes + 详情/联系人/历史 + 改名级联 |
| `src/routes/tags.ts` | 标签 | crudRoutes + 树 |
| `src/routes/auditLogs.ts` | 审计日志 | 只读列表/统计 |
| `src/routes/settings.ts` | 用户设置 | 键值对 upsert |

## 3.4 新手阅读顺序建议

**第一遍（建立直觉，半天）**：
1. `02-技术栈与工程配置` 的五条设计取向；
2. Budget `utils/api.ts`（前端的地基）；
3. 后端 `routes/helpers.ts` 的 `crudRoutes`（后端的地基）；
4. Budget `App.tsx` 路由 + `pageLoaders.ts` + `AppLayout.tsx`（把页面串起来）。

**第二遍（跟一条业务流走通全栈，一天）**：
- 选"销售机会"这条线：前端 `SalesOpportunityList.tsx` → `services/opportunityService.ts` → `api.ts` → 后端 `routes/index.ts`（守卫）→ `routes/opportunities.ts`（查询/状态机）→ `db/pool.ts`（参数化 SQL）→ 数据库表 `sales_opportunities`。
- 对照 04 章的"端到端旅程"图。

**第三遍（攻克难点，随需要来）**：
- 报价计算 → 07 章；蓝表 → 08 章；审批 → 09 章；工时 → 11 章。

## 3.5 本章小结

- 后端 = 入口 + 中间件 + 12 个路由模块 + 共享 helpers + 定时任务。
- Budget = 路由/布局 + 20 个 utils 文件 + 13 个 service 文件 + 14 个页面文件（含登录）+ 组件库。
- TR = 6 个业务页面 + 登录页（共 7 个页面文件）+ 大批 utils 纯函数 + 图表组件。
- 阅读顺序：地基（api.ts / crudRoutes）→ 一条业务流全链路 → 逐个难点。
