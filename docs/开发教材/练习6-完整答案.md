## 第 1 步 · 数据库：给交付项目加预算审批列

**目标**：`delivery_projects` 增加 `budget_status`（审批状态）与 `budget_approval`（审批结果 JSONB），与既有 `plan_status/plan_approval`、`cost_status/cost_approval` 同构。

**改动文件**：新建 `backend/migrations/046-add-delivery-budget-status.sql`

```sql
-- 046-add-delivery-budget-status.sql
-- 交付项目预算审批：与 plan/cost 审批同构（budget_status 状态 + budget_approval 结果 JSONB）
ALTER TABLE delivery_projects ADD COLUMN IF NOT EXISTS budget_status review_status NOT NULL DEFAULT 'draft';
ALTER TABLE delivery_projects ADD COLUMN IF NOT EXISTS budget_approval JSONB;
```

**同时同步权威 schema**：`BudgetEstimateApp/database/schema.sql` 的 `delivery_projects` 表内（`cost_approval` 行之后）加：

```sql
  budget_status       review_status NOT NULL DEFAULT 'draft',
  budget_approval     JSONB,
```

并在文件末尾"迁移兼容"区块（`actual_costs` 那一行附近）加：

```sql
ALTER TABLE delivery_projects ADD COLUMN IF NOT EXISTS budget_status review_status NOT NULL DEFAULT 'draft';
ALTER TABLE delivery_projects ADD COLUMN IF NOT EXISTS budget_approval JSONB;
```

**讲解**：`review_status` 枚举（draft/pending/approved/rejected）复用，与 plan/cost 完全一致，不用新建枚举。schema.sql 是"从零建库唯一权威"，改结构的迁移必须同一 commit 同步它（05 章纪律）——否则新库缺列，代码跑挂。

**验证**：
```bash
# 本地库执行迁移
PGPASSWORD='你的密码' psql -h 127.0.0.1 -U budget_app -d budget_estimate \
  -f backend/migrations/046-add-delivery-budget-status.sql
# 确认列存在
PGPASSWORD='你的密码' psql -h 127.0.0.1 -U budget_app -d budget_estimate \
  -c "\d delivery_projects" | grep budget
```

## 第 2 步 · 后端：审批类型白名单加入 budget

**目标**：后端认可 `budget` 这种审批类型。

**改动文件**：`backend/src/routes/approvals.ts`

```diff
-export const APPROVAL_TYPES = ['quotation', 'plan', 'cost', 'promote'] as const;
+export const APPROVAL_TYPES = ['quotation', 'plan', 'cost', 'promote', 'budget'] as const;
```

**讲解**：
- `APPROVAL_TYPES` 是创建接口的枚举白名单（C2 修复：非法值给 400 而非撞 PG 枚举 500）；
- **无需改 `approvalTypeToDupColumn`**：它的 fallback 分支本来就返回 `'delivery_id'`，budget 与 plan/cost 一样按交付去重，自动命中；
- **无需改 `approvalTypeToParentTable`**：fallback 返回 `'delivery_projects'`，budget 自动锁交付行。

**验证**：`cd backend && npm run build`（应全绿；此时还没有用 budget 的路径，但白名单已认）。

## 第 3 步 · 后端：创建审批的级联（置 pending）

**目标**：提交 budget 审批时，把交付的 `budget_status` 置为 `pending`（锁定"预算待审"状态）。

**改动文件**：`backend/src/routes/approvals.ts` 的 `POST /` 事务内，在 cost 级联块之后加：

```diff
       if (approval_type === 'cost' && delivery_id) {
         await client.query('UPDATE delivery_projects SET cost_status = $1, updated_at = now() WHERE id = $2', ['pending', delivery_id]);
       }
+
+      if (approval_type === 'budget' && delivery_id) {
+        await client.query('UPDATE delivery_projects SET budget_status = $1, updated_at = now() WHERE id = $2', ['pending', delivery_id]);
+      }
```

**讲解**：与 plan/cost 同款副作用——提交即把交付的预算状态推进到"待审批"。注意它在**同一个事务**里（`withTransaction` 的 client），审批插入失败则级联一并回滚。

## 第 4 步 · 后端：审批处理的级联回写

**目标**：审批人通过/驳回 budget 审批时，回写 `budget_status` + `budget_approval`（JSONB 留档）。

**改动文件**：`backend/src/routes/approvals.ts` 的 `POST /:id/records` 事务内，在 cost 回写块之后加：

```diff
       if (ar.approval_type === 'cost' && ar.delivery_id) {
         await client.query('UPDATE delivery_projects SET cost_status = $1, cost_approval = $2, updated_at = now() WHERE id = $3', [newStatus, appraisal, ar.delivery_id]);
       }
+
+      if (ar.approval_type === 'budget' && ar.delivery_id) {
+        await client.query('UPDATE delivery_projects SET budget_status = $1, budget_approval = $2, updated_at = now() WHERE id = $3', [newStatus, appraisal, ar.delivery_id]);
+      }
```

**讲解**：
- `appraisal = buildAppraisalJson(reviewer, action, comment, createdAt)` —— 审批结果 JSONB，与 plan_approval/cost_approval 同构 `{"reviewer","action","comment","createdAt"}`；
- 通过/驳回都写（`newStatus`），驳回后前端能看到 rejected 并重新提交。

## 第 5 步 · 后端：删除审批的回滚

**目标**：删除 pending 的 budget 审批时，把创建时置的 `budget_status='pending'` 回滚为 `draft`（F5 教训：否则交付永久卡在预算待审）。

**改动文件**：`backend/src/routes/approvals.ts` 的 `DELETE /:id` 事务内，在 cost 回滚块之后加：

```diff
       if (row.approval_type === 'cost' && row.delivery_id) {
         await client.query(`UPDATE delivery_projects SET cost_status = 'draft', updated_at = now() WHERE id = $1 AND cost_status = 'pending'`, [row.delivery_id]);
       }
+
+      if (row.approval_type === 'budget' && row.delivery_id) {
+        await client.query(`UPDATE delivery_projects SET budget_status = 'draft', updated_at = now() WHERE id = $1 AND budget_status = 'pending'`, [row.delivery_id]);
+      }
```

**讲解**：**条件更新**（`AND budget_status='pending'`）很关键——若期间又提交了新的 budget 审批（状态已非 pending），不覆盖它。

## 第 6 步 · 后端：权限拆分

**目标**：创建 budget 审批的权限 = "交付管理"（与 plan/cost 一致），而非审批管理。

**改动文件**：`backend/src/permissions.ts` 的 `APPROVAL_WRITE`

```diff
 export const APPROVAL_WRITE: Record<string, string[]> = {
   quotation: ['报价编制', PERM_ALL],
   plan: ['交付管理', PERM_ALL],
   cost: ['交付管理', '成本录入', PERM_ALL],
   promote: ['转线索/转机会', PERM_ALL],
+  budget: ['交付管理', PERM_ALL],
 };
```

**讲解**：`selectApprovalPerms(type)` 会查 `APPROVAL_WRITE[type]`；不加这一行的话，budget 会落到 fallback「审批管理」——只有审批管理权限的人能创建预算审批，交付经理反而不能，违背业务语义。**权限拆分是 A1 审计家族的核心防线**。

```ts
  // ── 预算审批提交（练习6：与 plan/cost 同款提交语义）──
  const handleSubmitBudget = useCallback(async () => {
    if (!project || submittingApproval) return;             // ⚠️ BU-3：防双击并发
    if (project.budgetStatus === 'approved') { msg.success('预算已审批通过'); return; }
    setSubmittingApproval(true);
    const ver = quotationVersionFull;
    const discountedPrice = ver?.discountedPrice || 0;
    const gp3ProfitRate = ver?.gp3ProfitRate || 0;
    approvalService.create({
      approvalType: 'budget',
      status: 'pending',
      quotationId: project.quotationId,
      deliveryId: project.id,
      salesNo: project.salesNo,
      clientName: project.clientName,
      projectName: project.projectName,
      amount: discountedPrice || project.contractAmount,
      totalCost: ver?.totalCost || 0,
      profitRate: rateToPercent(gp3ProfitRate),
      gp3: gp3ProfitRate,
      versionNo: ver?.versionNo || '',
      taxRate: quotationVersion?.taxRate ?? TAX_RATE,
      totalAccountingPrice: ver?.totalAccountingPrice || 0,
      discountedPrice: discountedPrice,
      discountRate: ver?.discountRate || 0,
      gp3Amount: Math.round(gp3ProfitRate * discountedPrice) || 0,
      submitter: modifierName,
    }).then(() => {
      setProject(prev => prev ? { ...prev, budgetStatus: 'pending' } : prev);
      msg.success('预算已提交审批，请前往审批管理模块查看');
    }).catch((err: unknown) => {
      msg.error('提交审批失败：' + ((err instanceof Error ? err.message : '') || '未知错误'));
    }).finally(() => {
      setSubmittingApproval(false);
    });
  }, [project, submittingApproval, msg, quotationVersionFull, quotationVersion, modifierName]);
```

（别忘了在页面顶部已有 import 处确保 `rateToPercent`、`TAX_RATE`、`CheckOutlined` 都已引入——它们在本页已被 plan/cost 流程使用，通常已存在。）

**讲解**：
- 前端只负责"把数据交出去"，**状态机与级联全在后端**（第 3~5 步）——前端提交后乐观置 `budgetStatus='pending'` 即可；
- 按钮颜色用 `COLORS.amber`（预算 = 琥珀色），与 plan(warning)/cost(success) 区分。

## 常见坑速查（背下来）

1. **漏改 `APPROVAL_WRITE`** → 交付经理无法提交预算审批（权限落到审批管理 fallback）。
2. **漏回滚（第 5 步）** → 删除 pending 审批后交付永久卡 `pending`。
3. **漏同步 schema.sql** → 新库建库缺列，`SELECT *` 返回列不存在的错。
4. **前端类型没加** → `project.budgetStatus` 是 `undefined`，`=== 'approved'` 恒 false，按钮行为错乱。
5. **忘了 `APPROVAL_TYPES`** → 提交 budget 直接 400。
6. **删旧审批后没验证条件更新** → 可能覆盖期间新提交的审批。
