## 11.1 系统概览

工时系统解决的是：**每个员工每天做了什么、花了多少小时、属于哪个成本中心，部门如何统计与分析。**

```
员工（TR TimeRecord 周网格填报）
   │  选择日期 → 时段（上午/下午/晚上）→ 起止时间 → 成本中心 → 工作内容
   │  按周提交（周日 20:30 后开放）
   ▼
后端（timerecording.ts）
   │  服务端权威重算：hours/hour_type/year/week_number
   │  校验：成本中心存在性 / 补录窗口 / 请休假规则 / 周提交闸门
   ▼
submitted → 审批（AdminApproval：单人单周分组）→ approved / rejected
   ▼
统计：Dashboard / StatsAnalysis / PersonalStats（按财年、成本中心类型、员工）
```

**三条硬规则**（都来自产品决策点，见 `docs/决策点清单-2026-08-14.md`）：
1. **补录窗口 = 当前周 + 前 4 周**（超过锁定只读）；
2. **补班日 = 工作日**（周末上班按正常出勤，不判加班、可请休假）；
3. **日净工时 = 8h**（全天请假 = 8h，单日请休假上限 8h）。

## 11.2 时段模型

一天的工时按三个时段组织（`frontend/src/utils/timeSlots.js`）：

```
SLOTS = [
  上午：08:00 - 12:30   (分钟 480~750)     ← 午间留 30 分钟用餐间隙
  下午：13:00 - 17:30   (分钟 780~1050)
  晚上：18:00 - 20:30   (分钟 1080~1230)
]
15 分钟步进；slotOf(start_time) 判定某条记录属于哪个时段
_other：无时段归属的旧记录（如 12:30 间隙起时）兜底容器
```

- **起时选项剔除时段末时刻**：比如上午的起时不能选 12:30（那样时长是 0，没意义）。
- 界面：一周 7 天 × 3 时段的网格，每格内可有多条任务行（`TaskRow`），行内四列：开始/结束/成本中心/工作内容。

## 11.3 服务端权威计算（backend/src/routes/timerecording.ts 顶部）

### 11.3.1 toMinutes：时间字符串 → 分钟

```ts
export function toMinutes(t?: string | null): number | null {
  if (!t) return null;
  const m = /^(\d{1,2}):(\d{2})(?::(\d{2}))?$/.exec(t);   // "HH:MM" 或 "HH:MM:SS"，锚定结尾
  if (!m) return null;
  const h = parseInt(m[1], 10), mi = parseInt(m[2], 10), sec = m[3] !== undefined ? parseInt(m[3], 10) : 0;
  if (h > 23 || mi > 59 || sec > 59) return null;          // 越界拒绝
  return h * 60 + mi;
}
```

要点：
- **正则锚定 `$`**：`"12:34:56:78"` 这类尾随垃圾不匹配 → null；
- **小时允许 1 位**（`\d{1,2}`）：`"8:00"` 合法；
- **越界拒绝**：`24:00`、`08:60`、`08:30:60` 都返回 null；
- 测试覆盖了所有这些边界（`timerecording-core.test.ts`）。

### 11.3.2 serverHours：净工时

```ts
export function serverHours(start?: string | null, end?: string | null): number {
  const s = toMinutes(start), e = toMinutes(end);
  if (s == null || e == null || e <= s) return 0;          // 无效/不跨午夜 → 0
  return Math.round(((e - s) / 60) * 100) / 100;           // round2 浮点纪律
}
```

- `08:00 → 12:30` = 4.5h；`18:00 → 20:30` = 2.5h；
- `end <= start` 返回 0（不跨午夜计负）；
- **round2**：`08:00 → 16:20` = 8.3333… → 8.33（对齐 DB `NUMERIC(4,2)`）。

### 11.3.3 serverHourType：加班判定

```ts
export function serverHourType(date?: string | null, start?: string | null, end?: string | null): 'normal' | 'overtime' {
  const s = toMinutes(start), e = toMinutes(end);
  // 晚时段(18:00-20:30)重叠：区间交集 > 0
  const evening = s != null && e != null && Math.max(0, Math.min(e, 1230) - Math.max(s, 1080)) > 0;
  const [y, m, d] = String(date || '').split('-').map(Number);
  const wd = (Number.isFinite(y) && Number.isFinite(m) && Number.isFinite(d)) ? new Date(y, m - 1, d).getDay() : -1;
  // 补班日（周末上班）= 工作日：周末加班判定豁免
  const weekendOvertime = (wd === 0 || wd === 6) && !(wd >= 0 && isMakeupWorkday(new Date(y, m - 1, d)));
  return (evening || weekendOvertime || (wd >= 0 && isStatutoryHoliday(new Date(y, m - 1, d)))) ? 'overtime' : 'normal';
}
```

加班 = **任一个命中**：
1. **晚时段重叠**：区间 `[18:00, 20:30]`（分钟 1080~1230）与记录有交集。`Math.max(0, Math.min(e,1230) - Math.max(s,1080)) > 0` 是"两个区间是否有重叠"的经典算法。
2. **周末**（`wd===0 || wd===6`），但**补班日除外**（D2 决策：补班日 = 工作日，不判加班）。
3. **法定节假日**（`isStatutoryHoliday`，硬编码 2025/2026 放假表，与前端 holidays.js 同步）。

### 11.3.4 isoWeekOf：ISO 周

```ts
export function isoWeekOf(dateStr: string): { year: number; week: number } {
  const [y, m, d] = dateStr.split('-').map(Number);
  const date = new Date(Date.UTC(y, m - 1, d));
  const dayNum = date.getUTCDay() || 7;                 // 周日=7（ISO 周一始）
  date.setUTCDate(date.getUTCDate() + 4 - dayNum);      // 周四所在周 = ISO 周
  const yearStart = new Date(Date.UTC(date.getUTCFullYear(), 0, 1));
  const week = Math.ceil((((date.getTime() - yearStart.getTime()) / 86400000) + 1) / 7);
  return { year: date.getUTCFullYear(), week };
}
```

**ISO 8601 周**的算法：一个周的归属由"该周的周四"决定（周四在哪个 ISO 年，整周就属于哪年）。这里 `date.setUTCDate(getUTCDate() + 4 - dayNum)` 把日期移到本周四。对齐 PG 的 `EXTRACT(WEEK/ISOYEAR)` 和前端 dayjs isoWeek——**跨年边界**（如 12 月 31 日是下一年的第 1 周）才不会对不上。

## 11.4 补录窗口与撤回窗口（D1 决策落地）

### 11.4.1 补录窗口

```ts
export function backfillWindowStart(now: Date = new Date()): string {
  const daysSinceMonday = (now.getDay() + 6) % 7;       // 周一=0…周日=6
  const monday = new Date(now.getFullYear(), now.getMonth(), now.getDate() - daysSinceMonday - 28); // −4 周
  ... return 'YYYY-MM-DD';   // 截止点 = 当前周周一 − 4 周
}

export function assertBackfillWindow(dateStr, now = new Date()): void {
  if (typeof dateStr !== 'string' || !isValidDateStr(dateStr)) return;
  if (dateStr < backfillWindowStart(now)) {
    throw new AppError(400, '该日期已超出 4 周补录窗口...');
  }
}
```

- 截止点 = **当前 ISO 周周一 − 4 周**（日期粒度、落在周界）；
- 早于截止点的记录：新增/修改/删除/提交一律 400；
- **前端冻结格子只是 UX，这里是权威防线**；
- `now` 由调用方注入（**asOf 约定**）——测试传固定时刻，不依赖真实时间（F12 硬约束）。

### 11.4.2 撤回窗口（前端 withdrawWindow.js）

```ts
isWithdrawable(r, now, windowMs)   // submitted 看 submitted_at、approved 看 reviewed_at，30 天内可撤
```

撤回语义：提交/审批后 30 天内，员工可撤回修改（回 draft 重新提交）。超过 30 天按钮禁用并提示。这是"撤回"三处重复逻辑收敛出的**纯函数**（F08），渲染期和事件处理共用同一个判定。

## 11.5 请休假规则（assertLeaveValid）

```ts
async function assertLeaveValid({ userId, date, hours, hourType, code, type, excludeId }) {
  if (!isLeaveCostCenter(code, type)) return;           // 非请假成本中心，跳过
  if (hourType === 'overtime') throw new AppError(400, '请休假不能用于晚班/周末/节假日时段');
  // 单日请休假合计 ≤ 8h（含本行，PUT 时排除自身）
  const dayTotal = await query(`SELECT COALESCE(SUM(hours),0) FROM time_records WHERE user_id=$1 AND date=$2 ...`);
  if (round2(Number(dayTotal) + hours) > 8) throw new AppError(400, '请休假每天最多 8 小时');
}
```

三条规则：
1. **请假必须用 LE 成本中心**（`A####-LE-###` 编码或类型 `leave`）；
2. **请假不能落在加班时段**（晚班/周末/节假日 = 服务端 hour_type 是 overtime）；补班日 = 工作日，可请假（D2）；
3. **单日合计 ≤ 8h**：`round2(存量 + 本次) > 8` → 拒绝。D3 决策核实了**日净工时 = 8h**（不是时段跨度 9h），所以全天请假 8h 天然在限内，上限保持 8h 不放宽。

⚠️ 注意 `round2(dayTotal + hours)`——SUM 累加在 float64 下会出 `4.1+3.9 = 8.000000000000002`，不 round 会误拒合法输入。**浮点纪律无处不在**。

## 11.6 角色派生（trRoleOf）

```ts
export const trRoleOf = (u) => {
  if (u?.role === 'director' || u?.role === 'admin') return 'director';   // 总监级
  const perms = u?.permissions || [];
  if (perms.includes('报价编制') || perms.includes('交付管理')) return 'manager';  // 方案·交付经理
  return 'employee';
};
export const isManager = (u) => trRoleOf(u) !== 'employee';
```

工时系统只有**三档**（没有 admin 概念，admin 按 director 级处理）：

| trRole | 谁 | 能做什么 |
|---|---|---|
| `director` | role === 'director' \|\| role === 'admin' | 全部 + 审核管理（AdminApproval） |
| `manager` | permissions 含报价编制/交付管理 | 分配任务、看综合分析 |
| `employee` | 普通员工 | 只填报自己的工时 + 个人统计 |

前端 `ProtectedRoute` 用 `minRole` 守卫路由（`/stats/analysis` 需 manager、`/admin/approval` 需 director）。

## 11.7 前端报工页难点：validateGrid 与 collectPayloads（TimeRecord.jsx）

### 11.7.1 数据模型

```js
grid = {
  '2026-08-17': {              // dateKey
    morning:  [row, row, ...], // 每条 row 是一行任务
    afternoon: [],
    evening: [],
    _other: [],
  },
  ...
}
row = {
  _key: 'client-temp-id',      // 前端行标识
  _new / _deleted,             // 脏标记
  date, start_time, end_time, cost_center, cost_center_type, task_description,
  status: 'draft'|'submitted'|'approved'|'rejected'|'locked',
  // ⚠️ hours/hour_type/year/week_number 前端不预置——后端权威重算
}
```

**脏标记模式**：`_new`/`_deleted` 让 UI 先改本地，保存时把增删改拆成三批。

### 11.7.2 validateGrid（纯函数，模块级便于测试）

```js
function validateGrid(grid, ccByFy) {
  for (const [dateKey, day] of Object.entries(grid)) {
    const dayMap = ccByFy[fyOfDateKey(dateKey)]?.map || {};   // 财年→成本中心映射
    for (const slotKey of Object.keys(SLOT_BY_KEY)) {
      const slotRows = (day[slotKey] || []).filter(r => !r._deleted);
      for (const r of slotRows) {
        if (!r.cost_center && !r.task_description) continue;   // 空行跳过
        if (!r.cost_center) return { error: '存在未选择成本中心的记录...' };
        if (!dayMap[r.cost_center]) return { error: `成本中心「${r.cost_center}」不存在...` };
        // 请休假不能用于晚班/周末/节假日（补班日豁免）
        if (dayMap[r.cost_center] === 'leave') {
          const wd = parseDateKey(dateKey).getDay();
          const weekend = (wd === 0 || wd === 6) && !isMakeupWorkday(dateKey);
          if (slotKey === 'evening' || weekend || isStatutoryHoliday(parseDateKey(dateKey)))
            return { error: `请休假不能用于晚班/周末/节假日时段...` };
        }
        // 起止时间合法 + 在时段范围内
        const sm = timeToMin(r.start_time), em = timeToMin(r.end_time);
        if (sm == null || em == null || em <= sm) return { error: '结束时间早于/等于开始时间...' };
        if (sm < slot.startMin || em > slot.endMin) return { error: `「${slot.label}」时段起止时间需在...` };
      }
      // 时段内多任务时间不得重叠
      const intervals = slotRows.map(...).sort((a,b) => a.sm - b.sm);
      for (let i = 1; i < intervals.length; i++)
        if (intervals[i].sm < intervals[i-1].em) return { error: '时段内任务时间段重叠...' };
    }
    // 请休假单日合计 ≤ 8h
    let leaveDayTotal = 0;
    for (...) for (const r of ...) if (r.cost_center && dayMap[r.cost_center] === 'leave')
      leaveDayTotal += hoursOf(r);
    if (leaveDayTotal > 8) return { error: `${dateKey} 请休假合计...超过 8 小时` };
  }
  return null;
}
```

**校验的层次**（从"必须"到"业务规则"）：
1. **基本完整**：成本中心不能空、不能无效；
2. **请休假规则**：LE 码不能用在加班时段（晚班/周末/节假日）；
3. **时间合法**：起止时间格式合法、end > start、落在时段范围内；
4. **不重叠**：同一时段内多条任务的时间段不能重叠；
5. **日上限**：请休假单日合计 ≤ 8h。

⚠️ 这个校验在前端做（提交前的 UX），**后端 `assertLeaveValid`/`assertBackfillWindow` 再权威校验一次**——两处口径一致（同源规则 + 决策点文档）。

### 11.7.3 collectPayloads（把 grid 拆成增删改）

```js
function collectPayloads(grid, ccByFy) {
  const deletes = [], updates = [], creates = [];
  for (...) for (const r of rows) {
    if (r._deleted) { if (r.id) deletes.push(r.id); continue; }
    if (!r.cost_center && !r.task_description) continue;   // 空白行跳过
    const payload = {
      date: r.date,
      start_time: r.start_time || null, end_time: r.end_time || null,
      cost_center: r.cost_center,
      cost_center_type: map[r.cost_center] || inferType(r.cost_center),
      task_description: r.task_description || null,
      // ⚠️ 不携带 hours/hour_type/year/week_number——后端权威重算（S4）
    };
    if (r.id) updates.push({ id: r.id, ...payload });
    else creates.push(payload);
  }
  return { deletes, updates, creates };
}
```

**关键设计**：payload **故意不带** `hours`/`hour_type`/`year`/`week_number`。为什么？因为这些都是服务端权威（按起止时间和日期重算），前端带着自己的计算结果反而可能覆盖权威值（尤其是跨年周的 week_number）。**前端只负责选时段、选成本中心、写描述**——"算了多少小时"这种判定完全交给后端。

### 11.7.4 保存与提交流程

```js
handleSave   // Promise.allSettled 并行：deletes → updates → creates，部分失败不中断整批
handleSubmit // submitBatch(draftIds)：只传 id 列表，后端原子提交
```

- **保存**用 `Promise.allSettled`：某一条失败不影响其他条保存；
- **提交**一次整周提交（`submit-batch`），成功前整周冻结（`weekCommitted`）；
- **撤回**：30 天窗口内逐条 `withdraw` 回 draft；
- **周切换竞态**：`loadSeqRef` 序号守卫——快速切周时，后发的慢请求不会覆盖先发的新数据。

## 11.8 统计口径（timeStats.js 纯函数）

```js
inferType(code)     // 按编码前缀推断类型：DE-部门 / -LE-请假 / -00-个人 / -S销售 / -E交付 / -W质保 → other
typeOf(r)           // 服务端类型优先 → 推断 → 老数据兜底
effectiveWorkHours  // 总工时 − 个人 − 请假（"有效工作"口径）
buildTypeHours(records)  // 按 5 业务类型（销售/交付/质保/部门/个人）+ other 聚合；请休假不参与聚合
checkTruncation     // 拉取条数到达 limit 时告警（防静默截断）
```

**开工率** = `effectiveWorkHours / attendanceHours`，其中：
- `attendanceHours = attendanceDays × 8 − leaveHours`（每日 8h，扣除请假）；
- 分子分母都按**员工注册日钳制**（`clampToRegDate`）——月中入职的员工，分母只算入职后应出勤天数，避免"分母全量、分子钳制"的不对称（#14 修复）。

## 11.9 本章小结

- 时段模型：三时段 + `_other` 兜底；15 分钟步进。
- 服务端权威：hours/hour_type/year/week_number 后端重算，前端不传。
- 三个决策点：补录窗口（当前周+前 4 周）、补班日 = 工作日、日净工时 8h。
- 前端 `validateGrid`/`collectPayloads` 纯函数化 → 可测；后端再权威校验。
- 角色三档（director/manager/employee）由 role + permissions 派生。
