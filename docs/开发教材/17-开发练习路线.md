## 练习 3 · 新增一个 CRUD 资源（全栈最小闭环）

**学习目标**：掌握"建表 → 路由 → 守卫 → 前端四件套"的完整配方。
**前置知识**：[13 后端模式](13-后端开发模式详解.md) 13.2。

**任务**：实现一个"客户联系人管理"页面（后端 `client_contacts` 表已存在）。

### 后端

1. 建 `backend/src/routes/contacts.ts`：
   ```ts
   import { Router } from 'express';
   import { crudRoutes } from './helpers.js';

   const router = Router();
   const fields = ['id', 'client_id', 'name', 'position', 'phone', 'email', 'decision_role', 'superior'];

   router.use(crudRoutes('client_contacts', fields, {
     orderBy: 'created_at DESC',
     searchFields: ['name', 'position'],
     excludeOnCreate: ['id', 'created_at', 'updated_at'],
     excludeOnUpdate: ['id', 'created_at', 'updated_at'],
   }));

   export default router;
   ```
2. 在 `routes/index.ts` 挂载 + 守卫：
   ```ts
   import contacts from './contacts.js';
   router.use('/contacts', requireAuth, writeGuard(WRITE_GUARD.clients), readGuard(READ_GUARD.clients), contacts);
   ```
   （联系人归客户管理权限。）

### 前端

3. `types.ts` 加 `Contact` 类型（对照 `Client` 与 `Contact` 已有定义）；
4. `services/contactService.ts`：
   ```ts
   import { api } from '../utils/api';
   import type { Contact } from '../types';

   export const contactService = {
     list: (clientId: string) =>
       api.get<Contact[]>(`/contacts?client_id=${clientId}&limit=${'100000'}`),
     create: (data: Partial<Contact>) => api.post<Contact>('/contacts', data),
     update: (id: string, data: Partial<Contact>) => api.put<Contact>(`/contacts/${id}`, data),
     remove: (id: string) => api.delete(`/contacts/${id}`),
   };
   ```
5. 注册四件套：`App.tsx` 路由 → `pageLoaders.ts` 懒加载 → `AppLayout.tsx` 菜单 → `permissions.ts` 路由权限；
6. 页面 `pages/ContactList.tsx` 照 12.1.1 列表骨架（可简化：一个 Table + 新增/编辑 Modal）。

### 测试

7. 若 `client_contacts` 有状态机字段，补排除列断言；没有就至少跑通门禁。

**验收**：页面能列表/新增/编辑/删除联系人；无权限账号调接口得 403；`npm run build` 全绿。

**常见坑**：
- 忘注册 `pageLoaders` → 路由 404 或加载旧页；
- 守卫权限集写错 → 只有查看权限的人也能写（检查 `WRITE_GUARD` 只放写权限）；
- 前端写请求没走 service → lint-naming 拦裸 fetch。

## 练习 4 · 加一个统计图表（分析型页面）

**学习目标**：useMemo 派生、SVG 图表、共享口径。
**前置知识**：[10 交付与销售分析](10-交付与销售分析.md)。

**任务**：在 Budget 的 `Dashboard.tsx` 加一张"各销售员当月赢单金额"柱状图（数据已由现有 `opps` 提供）。

**步骤**：
1. 读 `components/charts/VerticalBarChart.tsx` 的 props：`title`（可选）、`data: BarItem[]`（`{name, value, color?, tooltip?, displayValue?}`）、`format: 'K' | '%' | 'num'`、`height`、`topN` 等；
2. 在 Dashboard 加派生数据（产出 `BarItem[]`）：
   ```tsx
   import type { BarItem } from '../components/charts/VerticalBarChart';

   const salesmanWinData = useMemo<BarItem[]>(() => {
     const now = new Date();
     const map = new Map<string, number>();
     for (const o of opps) {
       if (o.status !== '赢' || !o.wonAt) continue;
       const won = new Date(o.wonAt);
       if (won.getFullYear() !== now.getFullYear() || won.getMonth() !== now.getMonth()) continue;
       map.set(o.salesman || '未分配', (map.get(o.salesman || '未分配') || 0) + (o.amount || 0));
     }
     return Array.from(map.entries())
       .sort((a, b) => b[1] - a[1])
       .slice(0, 8)
       .map(([name, value]) => ({ name, value }));
   }, [opps]);
   ```
3. 渲染（`title` 可选、`format="K"` 让金额显示为千元）：
   ```tsx
   <VerticalBarChart title="各销售员当月赢单金额" data={salesmanWinData} height={200} format="K" />
   ```

**验收**：柱图数据与 `opps` 手算一致；窄视口不破版（参考 12.4 陷阱 3）。

**常见坑**：
- 用 `wonAt` 而非 `updatedAt`（F05：财年/月份归集用业务事件时间）；
- 金额未税口径（`amount` 已是未税？对照 [07](07-报价成本计算详解.md) 的 B7 契约）；
- SVG 被全局 CSS 缩放 → 显式 chartWidth 或条件 ResizeObserver。

**进阶**：把这段派生逻辑提取成 `utils/analysisShared.ts` 的纯函数并写单测（这就是练习 7 的雏形）。

- 前端忘了 `firstAccessiblePath` 场景 → 全无权限用户死循环（B30 教训）。

## 练习 6 · 加一个审批类型（状态机全链路）★★★★★

**学习目标**：状态机、事务、迁移双轨、枚举同步、权限拆分——本练习 = 前五练习的总和。
**前置知识**：[09 审批状态机](09-审批状态机详解.md)、[13 后端模式](13-后端开发模式详解.md)。

**任务**：仿照现有 `quotation` 审批，新增 `budget`（预算）审批类型。交付项目提交预算审批 → 审批通过后交付进入"预算已批"状态。

> 📌 **有完整答案可对照**：本练习的每一步（含可应用 diff、端到端验证清单、回归自查）见 **[练习 6 完整答案：新增「预算审批」类型](练习6-完整答案.md)**。先自己写，卡住再查答案。

### 第 1 步：数据库

写 `backend/migrations/046-add-delivery-budget-status.sql`：
```sql
ALTER TABLE delivery_projects ADD COLUMN IF NOT EXISTS budget_status review_status NOT NULL DEFAULT 'draft';
ALTER TABLE delivery_projects ADD COLUMN IF NOT EXISTS budget_approval JSONB;
```
**同一 commit** 在 `schema.sql` 同步这两列（05 章纪律）。

### 第 2 步：后端审批类型

`backend/src/routes/approvals.ts` 顶部：
```ts
export const APPROVAL_TYPES = ['quotation', 'plan', 'cost', 'promote', 'budget'] as const;

export function approvalTypeToDupColumn(type: string): string {
  return type === 'quotation' ? 'quotation_id'
    : type === 'promote' ? 'opportunity_id'
    : 'delivery_id';              // budget 归 delivery_id（与 plan/cost 一样按交付去重）
}
```

### 第 3 步：创建时的级联（approvals.ts POST /）

在级联区块加：
```ts
if (approval_type === 'budget' && delivery_id)
  await client.query('UPDATE delivery_projects SET budget_status = $1 WHERE id = $2', ['pending', delivery_id]);
```

### 第 4 步：审批处理时的回写（approvals.ts POST /:id/records）

在级联回写区加：
```ts
if (ar.approval_type === 'budget' && ar.delivery_id) {
  await client.query('UPDATE delivery_projects SET budget_status = $1, budget_approval = $2 WHERE id = $3', [newStatus, appraisal, ar.delivery_id]);
}
```

### 第 5 步：删除审批的回滚（DELETE /:id）

```ts
if (row.approval_type === 'budget' && row.delivery_id)
  await client.query(`UPDATE delivery_projects SET budget_status = 'draft' WHERE id = $1 AND budget_status = 'pending'`, [row.delivery_id]);
```

### 第 6 步：权限拆分（permissions.ts）

```ts
APPROVAL_WRITE.budget = ['交付管理', '全部查看权限'];   // 预算审批的创建方须持交付管理
```
（`selectApprovalPerms` 自动生效，无需改 index.ts。）

### 第 7 步：前端

1. `ApprovalList.tsx`：类型标签映射加 `budget → 预算审批`；
2. 提交入口：在交付详情页加"提交预算审批"按钮，调 `approvalService.create({ approvalType: 'budget', deliveryId, ... })`；
3. `types.ts`：`DeliveryProject` 加 `budgetStatus`/`budgetApproval` 字段。

### 第 8 步：测试

`tests/approvals.test.ts` 补：
```ts
it('budget 审批去重列按 delivery_id', () => {
  expect(approvalTypeToDupColumn('budget')).toBe('delivery_id');
});
it('budget 在审批类型白名单内', () => {
  expect(APPROVAL_TYPES).toContain('budget');
});
```

**验收**：能创建/审批/驳回/删除 budget 审批，级联 `budget_status` 正确流转；门禁全绿；**家族清单 F01/F02 自查通过**。

**常见坑**：
- **枚举漏配**：`APPROVAL_TYPES` 加了，但前端标签映射、权限映射没加 → 显示 undefined（F08 + HMR 陷阱）；
- **级联回滚漏了**：删除审批不回滚 `budget_status` → 交付永久卡 pending（F5 教训）；
- **去重列错了**：budget 用错去重列 → 同交付可重复提交待审（K4）；
- **权限没拆**：只加白名单数组、没加 `APPROVAL_WRITE.budget` → 无交付管理权限也能提交预算审批（A1）。

## 练习 7 · 给共享函数立基准（进阶·性能与测试文化）

**学习目标**：单一来源（F08）、测试纪律（F12）、性能基线。
**前置知识**：[14 测试门禁](14-测试与质量门禁.md)。

**任务**：把练习 4 的"销售员赢单金额"派生逻辑提取成 `analysisShared.ts` 的纯函数，写单测 + 加进 bench。

**步骤**：
1. 提取纯函数（放进 `utils/analysisShared.ts`）：
   ```ts
   export function salesmanMonthlyWin(opps: SalesOpportunity[], year: number, month: number): Array<[string, number]> {
     const map = new Map<string, number>();
     for (const o of opps) {
       if (o.status !== '赢' || !o.wonAt) continue;
       const won = new Date(o.wonAt);
       if (won.getFullYear() !== year || won.getMonth() !== month) continue;
       map.set(o.salesman || '未分配', (map.get(o.salesman || '未分配') || 0) + (o.amount || 0));
     }
     return Array.from(map.entries()).sort((a, b) => b[1] - a[1]).slice(0, 8);
   }
   ```
2. 写单测（真实形状、asOf 不适用就用传入 year/month）：
   ```ts
   describe('salesmanMonthlyWin', () => {
     it('只统计当月赢单、按金额降序、取前 8', () => {
       const opps = [/* 造 3~4 条真实形状数据 */];
       const r = salesmanMonthlyWin(opps, 2026, 7);
       expect(r[0][1]).toBe(/* 期望 */);
     });
   });
   ```
3. 加进 `vitest.bench.config.ts` 收集的 bench 文件，跑 `npm run bench` 立基线；
4. 页面改用这个共享函数（删掉内联实现）。

**验收**：页面行为不变；新函数有测试；`bench` 有基线数字。

**常见坑**：
- 页面还留一份内联实现 → 两处口径又漂移（F08），**必须删掉旧实现**；
- bench 文件 `as any` → lint-naming 抓警告，用精确类型。
