# 15 本地开发环境

> **本章学习目标**
> 1. 从零把三个代码库 + 数据库跑起来；
> 2. 理解 `.env` 需要哪些变量、为什么；
> 3. 掌握常用命令与常见报错的排查。

## 15.1 前置条件

| 软件 | 版本 | 用途 |
|---|---|---|
| Node.js | 20+ | 三个库都依赖 |

## 15.3 准备数据库

### 15.3.1 建库 + 建用户

```bash
# 以 superuser（postgres）登录
psql -U postgres

CREATE DATABASE budget_estimate ENCODING 'UTF8';
CREATE USER budget_app WITH PASSWORD '你的密码';
GRANT ALL PRIVILEGES ON DATABASE budget_estimate TO budget_app;
\q
```

### 15.3.2 用 schema.sql 建结构

```bash
PGPASSWORD='你的密码' psql -h 127.0.0.1 -U budget_app -d budget_estimate \
  -f D:/109-BudgetEstimate/BudgetEstimateApp/database/schema.sql
```

> schema.sql 是"从零建库唯一权威"，包含全部表/枚举/约束/索引/触发器（05 章）。想有演示数据，可再执行部分迁移种子（如 `backend/migrations/008-*`），或从生产库 `pg_dump` 一份数据导入。

## 15.4 配置环境变量

### 15.4.1 后端 `backend/.env`

代码里强制要求的环境变量（缺失会 `process.exit`）：

```
# 数据库
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=budget_estimate
DB_USER=budget_app
DB_PASSWORD=你的数据库密码

# 服务
PORT=3001

# CORS：允许的前端来源（逗号分隔）
CORS_ORIGIN=http://localhost:5173,http://localhost:5174

# 认证（auth.ts 要求 ≥32 位）
JWT_SECRET=用随机工具生成一个至少32位的字符串

# 本地 HTTP 必须为 0（上 HTTPS 后设 1）
COOKIE_SECURE=0
```

⚠️ `.env` 在 `.gitignore` 里，**不入库、不共享**。

### 15.4.2 前端不需要 .env（有默认值）

- Budget 的 `api.ts`：`API_BASE = import.meta.env.VITE_API_BASE || '/api/v1'`——默认走 Vite 代理；
- Vite 代理：Budget 默认指向**生产服务器**（`118.89.92.58`），TR 默认指向 `localhost:3001`。

> 想本地连本地后端：启动 Budget 时设置 `VITE_PROXY_TARGET=http://localhost:3001 npm run dev`。想用 TS 环境变量更复杂的形式可看 Vite 文档，本项目用 shell 前缀即可。

## 15.7 常见报错与排查

| 症状 | 原因 | 解法 |
|---|---|---|
| 后端启动 `[FATAL] DB_PASSWORD...` | `.env` 缺 DB_PASSWORD | 补 `.env`（15.4） |
| 后端启动 `[FATAL] JWT_SECRET...` | JWT_SECRET 缺或 <32 位 | 生成 ≥32 位字符串 |
| 后端启动 `[FATAL] CORS_ORIGIN...` | CORS_ORIGIN 未设置 | 填前端地址 |
| 页面 401 循环跳登录 | cookie 没带上 / 后端要求 Secure | 本地 `COOKIE_SECURE=0`；检查 cookie 域与 path |
| Budget 列表显示生产数据 | 代理指向了生产服务器 | 用 `VITE_PROXY_TARGET=http://localhost:3001` 启动 |
| `npm run build` 报 lint-naming 蛇形 | 前端内部写了 snake_case | 改成 camelCase（或确属 API body 白名单） |
| `tsc -b` 不报错但心里发虚 | — | 确认用的是 `tsc -b` 而非裸 `tsc --noEmit` |
| 测试环境报 DB 连接 | 测试模块加载期要 DB 变量 | vitest.config 已注入桩值，若自己加测试文件别覆盖 env |

## 15.8 开发工作流（推荐节奏）

```
写代码 → 本地跑通 → 补单测 → npm run build（五关门禁）→ git commit → 部署
```

**提交信息风格**（从 git 历史看）：一句话概括"做了什么 + 为什么"。例如：
`修复 B30：无权限重定向死循环——改跳 firstAccessiblePath`

## 15.9 本章小结

- 三库依赖、建库、.env、启动、验证，一次配好以后都是重复动作。
- `.env` 四项：DB 连接 + PORT + CORS + JWT_SECRET。
- 常用命令与报错表先收藏，遇到问题先查表。

**本章练习**：按 15.2~15.5 完整跑通一次（三个服务都起来 + 登录）。然后在 `npm run build` 门禁里故意制造一个 lint-naming 错误（写一个 snake_case 变量），观察它如何拦截，再改回来。
