# 12 前端开发模式详解

> **本章学习目标**
> 1. 掌握三种页面形态的标准骨架：列表页 / 详情编辑页 / 只读分析页；
> 2. 精读报价编制页（QuotationPage）的保存链路——本项目最复杂的前端流程；
> 3. 系统梳理前端常见陷阱（HMR/列宽/浮点/竞态/守卫依赖）与修 bug 实战。

## 12.1 三种页面形态

### 12.1.1 列表页骨架（以 SalesOpportunityList 为原型）

```tsx
const [data, setData] = useState<T[]>([]);
const [loading, setLoading] = useState(false);

// ① 用 useCallback 包加载函数（引用稳定，可作 useEffect 依赖）
const load = useCallback(async () => {
  setLoading(true);
  try {
    const rows = await someService.list({ limit: LIST_LIMIT });  // 显式传全量上限
    setData(rows);
  } finally { setLoading(false); }
}, []);

// ② 挂载时加载
useEffect(() => { load(); }, [load]);

// ③ 筛选/派生用 useMemo，不 setState 存"过滤后的数组"
const filtered = useMemo(() => data.filter(...), [data, deps]);

// ④ columns 用 useMemo（防渲染期重建导致整表重渲染）
const columns = useMemo(() => [/* ... */], [deps]);

// ⑤ 弹窗用 <Modal open={visible}>；写按钮按权限门控
{hasPermission(user.permissions, ['新增物料', '全部查看权限']) && <Button>新增</Button>}
```

**为什么每一步这么写**（面试/自答要点）：
- `useCallback` 包裹加载函数：保证 `useEffect` 依赖数组稳定，不会因函数每次渲染都变而无限重跑；
- 筛选用 `useMemo`：避免"筛选结果又存回 state"导致二次渲染，也保证派生值只在依赖变化时重算；
- `columns` 用 `useMemo`：antd Table 的 columns 数组如果每次渲染重建，会触发**整表重渲染**（F11 性能家族）。

### 12.1.2 乐观更新（touch 模式）

SalesOpportunityList 的行内编辑：

```tsx
const touch = useCallback((id: string, updates: Partial<SalesOpportunity>) => {
  setData(prev => prev.map(o => o.id === id ? { ...o, ...updates } : o));  // 先改本地
  opportunityService.update(id, updates).catch(() => { /* 失败回滚或提示 */ });
}, []);
```

**先改界面、后调接口**——用户感觉"秒存"。代价是失败要处理（回滚/提示）。这是"响应式"和"最终一致"的取舍。

### 12.1.3 只读分析页骨架（以 Dashboard 为原型）

```tsx
// ① 一次 effect 并行拉多资源，单接口失败不拖垮整页
useEffect(() => {
  Promise.allSettled([oppList(), deliveryList(), clientList(), quoteList()])
    .then(([a, b, c, d]) => { setOpps(a.status === 'fulfilled' ? a.value : []); ... });
}, []);

// ② 全部统计用 useMemo 派生，复用共享口径
const monthlyKpi = useMemo(() => computeMonthlyKpi(opps, deliveries), [opps, deliveries]);
```

要点：**用 `Promise.allSettled` 而非 `Promise.all`**——某个接口挂掉不该让整页白屏。图表统一为共享 SVG 组件（`VerticalBarChart` 柱状图 + `PieChart` 饼图；柱状图全应用单源，支持 `displayValue` 多行文案 / `groupGaps` 分组 / `unit` 后缀 / `yTickCount` 刻度数等），KPI 卡复用 `<OverviewCards>`。

## 12.2 精读报价编制页（QuotationPage）的保存链路

这是全项目最复杂的前端流程，理解它对"复杂业务前端怎么做"有决定性帮助。

### 12.2.1 页面状态模型

```tsx
const [project, setProject] = useState<Project | null>(null);
// project = { id, salesNo, clientName, ..., currentVersion, groups: Group[] }
```

**单一大对象**作为页面状态：任何编辑都用"不可变更新"（`{ ...prev, field: value }`）修改它。这比多个分散的 useState 好管理。

### 12.2.2 三个 ref（防重入/版本隔离的关键）

```tsx
const savingRef = useRef(false);                  // 保存防重入锁
const groupsVersionRef = useRef<string>('');      // 当前"已保存组"属于哪个版本
const versionsWithGroupsRef = useRef<Set<string>>(new Set());  // 哪些版本已有组
```

`groupsVersionRef`/`versionsWithGroupsRef` 解决的是**版本隔离 + 回切**的幂等问题：
- 版本号变了 → 后端对旧组 id 会 INSERT 新组（新 id），前端必须把新 id 同步回 state，否则下次保存会再 INSERT → **重复组**；
- 版本回切（V1→V2→V1）→ 目标版本已存在旧组，需先按版本清理再重建，否则旧组+新副本并存。

这是"保存幂等"的经典难题，用两个 ref 记录"我上次把组存到哪个版本了、哪些版本有组"。

### 12.2.3 handleSave 的完整流程（简化结构）

```tsx
const handleSave = useCallback(async () => {
  if (savingRef.current) return;                 // 防重入
  if (isLocked) { messageApi.warning('此报价已锁定，无法修改'); return; }
  // ... 前置校验：客户名/项目名/范围必填、至少一个明细、物料编码都在组件库

  // 审批状态降级（B61/B4）：approved/rejected 保存 → draft
  const statusForSave = reviewStatusForSave(curVer.reviewStatus);
  if (statusForSave !== curVer.reviewStatus) messageApi.warning('...保存后将重置为草稿...');

  try {
    savingRef.current = true;
    const isNew = project.id.startsWith('proj-');
    if (isNew) {
      // 新建：create 项目 → saveVersion → saveGroups → syncQuotation
      const created = await projectService.create(buildProjectPayload(project, { withSalesMeta: true }));
      const sv = await projectService.saveVersion(created.id, buildVersionPayload(curVer, summary, {...}));
      const idMap = await saveGroups(created.id, sv.id, project.groups);
      const syncResult = await syncQuotation(versionForSave, statusForSave, created.id);
      // 回写 state：把临时 id 换成后端真实 id，否则下次保存又当新建
      setProject(prev => ({ ...prev, id: created.id, groups: prev.groups.map(g => ({ ...g, id: idMap.get(g.id) || g.id })), currentVersion: {...} }));
      navigate('/quotations/' + qid, { replace: true });   // 新报价跳到正式 URL
    } else {
      // 更新：update 项目 → saveVersion → （版本隔离处理）→ saveGroups → syncQuotation
      ...
    }
  } finally { savingRef.current = false; setIsSaving(false); }
}, [project, ...]);
```

**值得学习的要点**：
1. **保存链路是"多接口编排"**：create → saveVersion → saveGroups → syncQuotation，每步返回的 id 要喂给下一步；
2. **id 回写**：后端生成真实 id（前端用 `proj-xxx` 临时 id），必须同步回 state，否则"临时 id"逻辑判断（`isNew`）会错乱；
3. **防重入锁**：`savingRef.current` 同步挡双击；`setIsSaving` 控制按钮 loading 再挡一层；
4. **状态降级提示**：改过已通过/已驳回的报价，保存后自动回草稿并提示用户（B4 UX 修复，不再静默）。

### 12.2.4 提交审批（handleSubmit）

```tsx
// 保存成功后，提交审批 = 调 approvalService.create({ approvalType: 'quotation', quotationId, ... })
// 后端会级联：报价置 pending、锁定等
```

前端只负责"把数据交出去"，**状态机在后端**（09 章）。

## 12.3 组件分层与共享

```
pages/       路由页面：编排数据 + 状态（不写公式、不裸 fetch）
components/  业务组件：接收 props 渲染，内部可再拉数据
  ├─ charts/    图表（VerticalBarChart 等）
  ├─ client/ material/  按域分包
  └─ shared/   跨页共享（OverviewCards）
utils/       纯函数：calculations / blueTableCalculation / analysisShared / constants / chartFonts / chartFrame（图表字号与框线单源）
services/    接口薄封装
```

**判断"逻辑该放哪"的三问**：
1. 会被两个页面用吗？→ utils/ 或 services/；
2. 会被两个组件用吗？→ components/shared 或独立组件；
3. 只是这个页面用的展示逻辑？→ 留在页面里（用 useMemo）。

## 12.4 前端常见陷阱与修 bug 实战

### 陷阱 1：HMR 下 mock 数据不刷新 / 新枚举漏配显示

- `useState(初始值)` 的初始化器**不响应 HMR**——改了初始值热更新后 state 还是旧的。改初始数据要整页刷新。
- **新增枚举必须同步所有显示位置**：比如给 `node_status` 加一个新值，凡是 switch/映射它颜色的地方都要加，否则新值渲染出来是 undefined 色。这是家族缺陷 F08 + 记忆 `hmr-mock-data-not-reflecting`。

### 陷阱 2：antd Table 列宽被压缩

症状：窄屏下列被压成细条。修复三件套：
```tsx
{ title: '金额', dataIndex: 'amount', onCell: () => ({ style: { minWidth: 120, maxWidth: 120, width: 120 } }) }
// + 外层 <Table scroll={{ x: 1248 }} />
```
`onCell` 内联样式 + `scroll.x`。详见记忆 `antd-table-column-width-enforcement`。

### 陷阱 3：全局 CSS 把 SVG 缩放变形

症状：手写 SVG 图表渲染高度失真、传 height/padBottom 参数"不生效"。
根因：全局规则 `.app-content svg { max-width: 100%; height: auto }` 让 SVG 按 viewBox 比例缩放，而容器宽度 ≠ viewBox 宽度。
修复：VerticalBarChart 用**条件 ResizeObserver**（未显式传 chartWidth 时启用）或显式 chartWidth。见记忆 `session-summary-2026-08-14-ui-fix`。

### 陷阱 4：浮点显示噪声

`12.300000000000001` 这种显示。规则：**显示 round、存储不 round**。MoneyInput 就是"显示时取整展示（`formatMoney`/`Math.round` + `toLocaleString`），state 里存原始浮点"——否则没改动也会被误判为"字段已改"。

### 陷阱 5：快速操作竞态（切周/切页/连点）

- 快速切换数据源（TR 切周 / Dashboard 切财年 / 列表切筛选）：`useRef` 序号守卫（TR 的 `loadSeqRef` 是范例）——后发请求不得覆盖新数据；Budget 的 QuotationPage 用 `savingRef` 防保存重入；
- 打开编辑弹窗：`pending ref` 防连点（B5 修复）；
- 保存/提交：`savingRef` 防重入 + loading 按钮。

### 陷阱 6：useCallback 状态守卫必须入 deps

```tsx
// ❌ 错：守卫闭包捕获了旧状态
const canSubmit = useCallback(() => rows.every(isValid), []);

// ✅ 对：守卫引用的状态必须进 deps
const canSubmit = useCallback(() => rows.every(isValid), [rows]);
```
否则守卫永远用初始的 `rows` 判断，提交被误拦或误放行。这是 2026-08-14 审计的教训。

### 陷阱 7：columns/options 渲染期重建

映射数组/列配置如果在渲染函数里字面量定义，每次渲染都是新引用 → 子组件（memo）重渲染 / 整表重渲染。**一律 useMemo + 空依赖或稳定依赖**。

## 12.5 前端性能基线（什么时候该担心）

`docs/性能基准基线.md` 记录了批量纯函数的耗时基线（如 10 万条工时聚合 25ms）。**大型重构触碰热路径时**跑 `npm run bench` 对比。普通页面开发不用在意。

## 12.6 本章小结

- 列表页/详情页/分析页三种骨架，各有各的编排模式。
- 复杂保存链路 = 多接口编排 + id 回写 + 防重入 + 状态降级。
- 组件分层 + 纯函数下沉 + useMemo 稳定引用。
- 七个陷阱是前端事故的高发区，提交前对照自查。
