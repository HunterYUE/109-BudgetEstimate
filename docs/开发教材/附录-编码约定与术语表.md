## A. 编码约定（三库统一）

### A.1 命名规范（camelCase / snake_case 边界）

| 场景 | 规范 | 示例 |
|---|---|---|
| 前端内部变量/类型/函数 | camelCase | `clientName`、`totalCost` |
| 后端 DB 列 | snake_case | `client_name`、`total_cost` |
| 前端发给后端的请求体字段 | 由 api.ts 自动 `toSnake` | 写 `{ clientName }`，线上变 `client_name` |
| 后端返回给前端的字段 | 由 api.ts 自动 `toCamel` | 线上 `client_name`，页面见 `clientName` |
| TR 前端（不转换） | 直接用后端 snake_case | `cost_center`、`start_time` |

**守门人**：`scripts/lint-naming.cjs`（Budget build 第一步）扫前端 src，禁止蛇形键名与裸 `fetch()`。

### A.2 注释规范（详 `docs/注释规范.md`）

```ts
// ── 区段标题：行注释、双侧闭合 ──
/** 函数单行说明：中文，散文式 */
/** 需要参数语义时用多行 JSDoc（少数情况） */

// ⚠️ A105 修复：决策历史，只写"为什么当前不变量"，不写"此前怎样"
```

- ⚠️ 编号（A1/C106/B61 等）是**历史批次号**：存量不重排、不回收、不按语义归类；新增沿用所在库字母池递增（后端 A/F/L/M/K/H/C/S，Budget B/A/L/D/F/M，TR C/S/T/L/A/B）。
- 注释一律中文（技术术语、路径除外）。

### A.3 状态机纪律

- `status`/`locked`/`review_status`/`plan_status`/`cost_status`/生命周期时间戳 = **服务端权威**；
- 通过 `excludeOnCreate/excludeOnUpdate` 或专用流程流转，通用 CRUD 禁直设；
- 前端传值只是建议，后端永远重算/校验。

### A.4 金额与浮点

- 全应用金额按**未税**处理，仅概算汇总三处含税（B7 契约定稿）；
- 聚合后一律 `round2`/`round1` 去浮点噪声；
- 默认值用 `?? 1` 不用 `|| 1`（`|| 1` 会吞掉合法 0）。

### A.5 安全底线

- SQL 一律参数化；
- 用户可控文本进 HTML 前 `escapeHtml`；导出文件名 `fileSafe` 清洗 `\/:*?"<>|`；
- 越权/越级：`assertCanManage` + 权限白名单；
- 登录失败统一文案 + 假 bcrypt 比较 + 限速。

## E. HTTP 状态码与响应形状约定

### 状态码（后端 `errorHandler` + 各路由）

| 状态码 | 含义 | 典型来源 |
|---|---|---|
| 200 | 成功 | GET 列表、PUT/DELETE 成功、登录成功 |
| 201 | 创建成功 | POST /approvals、POST 创建实体 |
| 204 | 无内容成功 | 无 body 的响应（`api.ts` 特判） |
| 400 | 请求无效 | `AppError(400)`：缺参、枚举非法、日期越界、请休假超限 |
| 401 | 未登录 / 凭证失效 | `requireAuth`：无 cookie、token 过期、账户停用、改密吊销 |
| 403 | 权限不足 | `requirePermission`、`assertCanManage` 越级、`trAppGuard` 跨应用拦截 |
| 404 | 资源不存在 | 记录查不到（`RETURNING` 无行、`SELECT` 无行） |
| 409 | 状态冲突 | 重复提交待审、终审再操作、被引用禁止删除、转交付重复 |
| 413 | 上传超限 | multer `LIMIT_FILE_SIZE` |
| 500 | 服务器错误 | 未捕获异常（**不泄漏 SQL/表结构**，detail 只进服务端日志） |

### 响应形状（`helpers.ts` A21 约定）

- **创建/更新**返回受影响实体本身（前端要回填 `id`，如创建用户/报价后需要新 id）；
- **纯动作**（删除/重置密码/登出）返回动作信封：删除 `{deleted:true, id}`、重置密码 `{success:true}`、登出 `{ok:true}`；
- **错误**统一 `{ error: '中文消息' }`（`api.ts` 的 `!res.ok` 分支解析 `body.error` 抛 `ApiError`）；
- 前端 `api.ts` 只依赖 HTTP 状态码（`res.ok`），不解析信封字段——两类形状互不冲突。
